# SLIM 與 AiF-like reproduction：256-KiB leaf GEMV 的來源邊界

2026-11-03 UTC。範圍：只讀公開論文、作者可見的 source、既有 AiF-like reproduction source；未跑程式、模型、RTL 或模擬，未接觸任何本輪 payload，亦未聯絡作者。對 SLIM 使用固定版本 [arXiv:2507.09201v1](https://arxiv.org/html/2507.09201v1)。

## SLIM 已有什麼；尚未看見什麼

- **直接的系統 prior 很強。** §3.4、§5.2、§5.4 明確支援 FFN/MoE 權重置於 NAND、低秩 predictor 控制取用哪些權重、普通 NAND 讀取後在 channel 或 NAND die 附近數位 GEMM；die-level PE 從 NAND data register 到 ONFI 的資料路徑 multiplex 取數。§7.1 Table 3 列 DeepSeek-16B、Mixtral 8×7B MoE 模型。不能將「MoE＋low rank＋依輸入選權重＋普通 NAND die-level GEMM」分別稱為首次。該 paper 的低秩方法不是 whole expert output surrogate：§4.1–4.2 明定 `|X L R| > threshold` 預測 gate neurons，依 mask 保留原 gate/up/down 權重與計算；L、R 的校準以 gate-projection reconstruction 為目標，原文設定 rank 為 embedding dimension 的 1/4。其 MoE overhead §7.5 明言每個 activated FFN 需多次 sparsity prediction，**不是已明說共用 layer-wide 輸入投影**。不同模型不代表一定有效：仍需 matching quality、capacity、host/DRAM projection、read/PE 成本的合理基準。
- **跟目前 leaf bank 的差異有文獻上的具體範圍，不是 absence 證明。** 讀過 §4–6 的文字與公式後，未在 v1 找到以 shared `P_l x` 作全層共用 key／features，依 input 選 per-expert finite affine leaf `A_{e,c}P_lx+b_{e,c}`、以此取代完整 gated FFN 的 256-KiB leaf bank。SLIM 已做 input-conditioned 選擇原 FFN neuron vectors，故不能把「input 選擇 flash 資料」當差異；可檢驗的差異是 **被選內容和算子**、一個共享 projection 的計算與儲存成本、其模型品質，以及真 NAND/page/host cache 幾何。SLIM 沒直接描述上述方法，並不代表別的文獻也沒有；僅憑未找到完全同義標題不能宣稱新意。
- **資源點不是 AiF native 硬證據。** Table 2 的 die-level 規格是 16 MACs、64 KB SRAM、0.07 mm²/die、27.0 mW/die @1 GHz；§7.5 說 ASIC systolic arrays 先 TSMC 40 nm synthesis 再 scale 到 22 nm。這是其**另一設計的估算**，不是 AiF（45 nm、200 MHz）的 16 lanes，也不是已量測 silicon。§5.4 的 SRAM 功能是 input buffer 和 output/partial-sum buffer；沒有證明整個 64 KB 可作一頁權重 cache，更沒有給出 input/output/其他容量分割和同時 ports。若假設 256 KiB leaf 被四 chips 平均切成每 chip 64 KiB，僅是 bytes 算術；不能宣稱每 chip 的 64 KB PE SRAM 可無額外成本存 resident shard。
- **已做足夠多的 page 工作，不能將其重新包裝為首創。** §5.4–6.1 已描述 output-stationary、batch inputs 共用讀一次的 weights、partial sums 本地 buffer、fused gate/up/down vector 和 page-aligned vector packing；§7.4 明確指出 page 未填滿及小 embedding 導致的固定讀延遲損失。§6.2 的並行是兩個獨立 input sequences 在 DRAM-PIM/SSD-NSP 的 pipeline，不等於同 bank weight cache 與 host 正常 read 競爭或同頁 early read 命中。
- **ordinary read 並不等於同一硬體配置。** Table 2 假設 SLC：2 planes、4-KB pages、3 µs tR；TLC：2 planes、16-KB pages、40 µs tR。這些數值不能當 AiF 四-plane、be-enc ordinary LSB 28 µs 的證據或直接複製。§7.6 把 multi-plane independent read 等列為預期的進一步改進，並非直接聲稱其模擬已實作 AiF-like 4-plane 合約。§7.1 說性能結果由 modified MQSim / TransPIM 事件/週期模擬，並非實體 NAND+PE 測得的短向量吞吐。

## §6.3 的 mapping 和 early-read 的證據界線

SLIM §6.3 明文說 conventional read/write 與 custom inference commands 共用額外 LPA-to-buffer mapping，避免 redundant reads 和複製 L2P mapping，且另考慮 internal DRAM bandwidth 競爭。這是應正視的**直接 prior**，不得說它完全沒有兩模式支援或 mapping 管理。但本文文字沒有明定：一般讀是否把**同一實體 weight page 的資料**保存在何種 bounded cache 中；接續 NSP GEMM 是否從該 cache 命中與跳過 sensing；dirty/coherence、cache eviction、ECC 狀態、TLB/tag、same-bank arbitration 及 counterfactual 命中/失敗時序。因此，不能將其 mapping 的「without redundant reads」直接提升成已驗證的「普通早讀後，同一 cache 供 in-flash GEMV 使用」functional 機制，也不能倒過來說論文斷言永遠不支援。需要作者具體實作或獨立微架構/功能規格才能裁定。

## AiF-like reproduction：哪些是事實、哪些不是功能基準

以下固定 [NVMeVirt reproduction commit `c01dbef3893eefcbace4dbad03ceee32a37b6048`](https://github.com/Chanyeong-Yoon/nvmevirt-aif/tree/c01dbef3893eefcbace4dbad03ceee32a37b6048)，未建立它和 AiF 原作者的關係，不能把此版本代稱官方 AiF artifact：

- 作者 [AIF.md](https://github.com/Chanyeong-Yoon/nvmevirt-aif/blob/c01dbef3893eefcbace4dbad03ceee32a37b6048/AIF.md) 明寫 POST 只更新 mapping / placement metadata，weight bytes 不放進 emulated flash；GEMV 只搬 input、checksum、回傳 deterministic dummy。因而普通 load 和 GEMV 不能對同一真實 weight payload 做數值等價或 cache reuse 檢驗。此 source 可用於檢查該 reproduction 的 command 格式、布局 metadata 和其明示的 timing model，不能作數值 GEMV 或真 PE 基準。
- [GEMV handler](https://github.com/Chanyeong-Yoon/nvmevirt-aif/blob/c01dbef3893eefcbace4dbad03ceee32a37b6048/conv_ftl.c#L1683) 檢查 `AIF_GEMV_F_DUMMY_OUTPUT`，依 layout snapshot 算延遲，再填 dummy；[`aif_estimate_gemv_delay`](https://github.com/Chanyeong-Yoon/nvmevirt-aif/blob/c01dbef3893eefcbace4dbad03ceee32a37b6048/conv_ftl.c#L1049) 的 channel availability 為每次函數呼叫初始化的局部 arrays，chip 計時為 `max(max_plane_pages × 9700 ns, page_bytes / 6.4 GB/s)`，這是**使用禁止的 CR-read 9.7 µs 的模型**，不是 ordinary 28 µs，也沒有顯示 lane count/短 row reset。
- [normal `conv_read`](https://github.com/Chanyeong-Yoon/nvmevirt-aif/blob/c01dbef3893eefcbace4dbad03ceee32a37b6048/conv_ftl.c#L2036) 使用 LPN→PPA 與 `ssd_advance_nand`；[`AIF_GEMV` timing path](https://github.com/Chanyeong-Yoon/nvmevirt-aif/blob/c01dbef3893eefcbace4dbad03ceee32a37b6048/conv_ftl.c#L2258) 走獨立估算並以 request start 加 delay。從這些已核函式看不出後者更新普通讀的同一 per-LUN NAND busy schedule 或保持 page payload，因此**不提供可驗證的共同 bank 爭用／命中時序**；不能將局部函式閱讀推論成整個 emulator 不存在其他排程限制。普通 page-read metadata 共用 L2P 不等同共用 cache 內容。

結論：SLIM 是本輪應公平正面面對的強 MoE/NAND prior 和可行的性能/品質對照概念；目前找到的公開作者相關 software 與 AiF-like reproduction 都不能直接充當所要求的「同 payload、同 bank、可觀察 cache 命中」功能實作，也不能證明 AiF 的 PE lane 或服務率。若後續要建立可比較基準，需明確實作同一份 W8 map bytes 和量化契約、共享有限容量 cache 與命中/失效、普通讀和 GEMV 共用 bank 的排程及並發限制，並對計算路徑、緩衝及傳輸記帳；這是未執行的驗證需求。
