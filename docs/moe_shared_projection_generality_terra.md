# Routed MoE 共用 layer input 的適用範圍與容量邊界

2026-11-03 UTC；只讀模型作者 config/forward 與 primary papers，未接觸模型權重、候選程式、activation、目標、books、evaluation examples 或 FIT 結果。下列是原始模型的**資料流**及靜態量綱，不是本方法的數值等價或品質證明。Transformers 原始碼以 release tag 指定；checkpoint config 以 Hugging Face repository revision 指定。

## 已核對的 routed expert 和 router

令 `x` 為**同一 layer、同一 token、進 MoE 前的實際 hidden vector**（包含該模型 MoE 前 layer norm 等），則以下原始 forward 所選的 routed FFN 接收同一 `x`。因此對這些實作，可在每個 layer/token 計算一次 `z=P_l x`，再將同一 z 用於各 routed expert 的 surrogate；這是代數上可安排的共享，並不保證低秩 z 足以保持模型品質、原數值精度、或保證實際加速。若所有 experts 也共用**同一棵 tree 及同一 region 定義**，亦可查一次 tree；若 tree/輸入正規化/threshold 是 per-expert，則仍要按定義逐 expert 評估，不能先假設免費共享。

- **DeepSeek-V2-Lite（有 shared）**：[作者 checkpoint config，revision `604d5664dddd88a0433dbae533b7fe9472482de0`](https://huggingface.co/deepseek-ai/DeepSeek-V2-Lite/blob/604d5664dddd88a0433dbae533b7fe9472482de0/config.json) 設 H=2048、64 routed、top-6、2 shared、27 layers 首層 dense、`norm_topk_prob=false`、scale=1；[作者 forward](https://huggingface.co/deepseek-ai/DeepSeek-V2-Lite/blob/604d5664dddd88a0433dbae533b7fe9472482de0/modeling_deepseek.py) 的 `DeepseekV2MoE.forward` / `moe_infer` 傳相同原 hidden states 給各選中 expert，shared FFN 接收同一 identity，輸出另加。`MoEGate` 先對全 experts 的 logits softmax，按設定 greedy top-k；只有 `top_k>1 and norm_topk_prob` 才歸一化，否則乘 `routed_scaling_factor`。該 checkpoint 的 selected weights **不必總和為一**。同檔的 grouped option 是可配置的分組 selection，該 checkpoint `n_group=1`、`topk_method=greedy`。
- **Mixtral 8×7B（無 shared）**：[官方 checkpoint config `fc7ac94680e38d7348cfa806e51218e6273104b0`](https://huggingface.co/mistralai/Mixtral-8x7B-v0.1/blob/fc7ac94680e38d7348cfa806e51218e6273104b0/config.json) 為 H=4096、E=8、K=2；[Transformers v4.44.2 `MixtralSparseMoeBlock`](https://github.com/huggingface/transformers/blob/v4.44.2/src/transformers/models/mixtral/modeling_mixtral.py#L602) 先 full softmax、top-k、**再歸一化選中 weights**，依 expert dispatch 相同 token 的 `hidden_states`，乘 routing weight 後加總。該程式的 router jitter 是 training branch，不能作 inference 输入不同的例子。
- **OLMoE-1B-7B-0924（無 shared）**：[官方 checkpoint config `6d84c48581ece794365f2b8e9cfb043c68ade9c5`](https://huggingface.co/allenai/OLMoE-1B-7B-0924/blob/6d84c48581ece794365f2b8e9cfb043c68ade9c5/config.json) 是 H=2048、E=64、K=8、16 layers、`norm_topk_prob=false`；[Transformers v4.46.3 `OlmoeSparseMoeBlock`](https://github.com/huggingface/transformers/blob/v4.46.3/src/transformers/models/olmoe/modeling_olmoe.py#L558) 對全部 logits softmax、top-k、只在 flag 為真時歸一化；相同 token hidden vector 經選中 experts，乘其實際 weights 再 `index_add_`。checkpoint 的 top-k weights 無需和為 1。
- **Qwen1.5-MoE-A2.7B（有 shared）**：[官方 config `1a758c50ecb6350748b9ce0a99d2352fd9fc11c9`](https://huggingface.co/Qwen/Qwen1.5-MoE-A2.7B/blob/1a758c50ecb6350748b9ce0a99d2352fd9fc11c9/config.json) H=2048、E=60、K=4、`norm_topk_prob=false`；[Transformers v4.44.2 `Qwen2MoeSparseMoeBlock`](https://github.com/huggingface/transformers/blob/v4.44.2/src/transformers/models/qwen2_moe/modeling_qwen2_moe.py#L600) 沿用全 expert softmax → top-k → 可選 normalize，且同一 hidden token 傳入每個選中 expert。shared expert 接收相同 hidden state，但其輸出乘**獨立 sigmoid shared gate**再相加；不要把它當 DeepSeek 的無 gate shared 加法或硬套 routed alpha 正規化。
- **DeepSeek-V3（有 shared、不同 router）**：[官方 config `e815299b0bcbac849fa540c768ef21845365c9eb`](https://huggingface.co/deepseek-ai/DeepSeek-V3/blob/e815299b0bcbac849fa540c768ef21845365c9eb/config.json) 設 `scoring_func=sigmoid`, `topk_method=noaux_tc`, `norm_topk_prob=true`, `routed_scaling_factor=2.5`；[作者 inference model `Gate`/`MoE`](https://github.com/deepseek-ai/DeepSeek-V3/blob/9b4e9788e4a3a731f7567338ed15d3ec549ce03b/inference/model.py#L498) 由 sigmoid score 加 bias／group masking 作 selection，再從**未加 bias 的原 score**取權重，對選中 sigmoid weights 正規化後乘 route scale。故其輸出 routed alpha 總和約 2.5（精度／舍入除外），並非 Mixtral 的 1，也非 V2-Lite 的 raw selected softmax。forward 中每個選中 expert 讀取同一 `x[idx]`，shared MLP 另讀 x 加總。這是作者 inference source 的行為，不以 V2 remote code 冒充 V3。

以上 router 的浮點 dtype、tie handling、grouped masking、動態 alpha、shared branch 和求和順序均是數值契約的一部分；不能自行把各模型 alpha 改成歸一化 1 或把 shared 路徑省略。以上 links 沒證明任何特定非官方 backend / quantized graph 的 bitwise 相同結果；如以不同 runtime 作 teacher，應檢查其 graph 和數值語義。

## 變種邊界：何時一次 `P(x)` 不再直接成立

- **專家內部差異本身不構成硬性否決。** 不同 intermediate width、固定 expert-specific 線性/非線性前處理仍可把整個 `F_e(T_e(x))` 定義成各自的 teacher output，再以共同的 `P(x)` 訓練各自 leaf；這是變更擬合目標，**不保證**有限 rank 或現有 weights 擬合成功，也不能把非線性 `T_e` 與 P 交換，更不是 finite precision exact folding。shared expert、不同 width 不自動表示 routed experts 的 x 不同。也不要因 mixed modalities 的存在，就斷言以上五個 checkpoint 有 per-expert input transforms。
- **具體不同輸入變種：** [From Sparse to Soft Mixtures of Experts, ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/file/79fea214543ba263952ac3f4e5452b14-Paper-Conference.pdf) §2 以 expert/slot 專屬的權重，將多個 token 混合後形成各 expert inputs。這是 soft/slot MoE，**不是上述標準 token-routed 解碼模型，也不能當普遍商用 LLM 的統計證據**；同一 token 的一次 `P(x_t)` 不能直接代替所有 expert 的不同 slot 輸入或消除 token 混合／slot 計算。若 P 為線性，確可先投影後加權組合，但仍需各 slot 的混合權重與計算，且量化運算未必可交換。
- **真的額外狀態或路由依賴：** [Mixture of Attention Heads, EMNLP 2022](https://aclanthology.org/2022.emnlp-main.278/) §4 式 (10)–(12) 的被選 attention expert 是 `E_i(q_t,K,V)`，不能一般地當成只由當下 `q_t` 決定的 tokenwise FFN `F_i(q_t)`；不同歷史 `(K,V)` 可造成不同輸出。要適用須保留並處理所需歷史狀態或擴充 teacher/特徵，不能單靠固定 `P(q_t)` 聲稱通用。這是 routed attention 研究變種，不是上述模型 FFN 反例。
- [Expert Choice, NeurIPS 2022](https://arxiv.org/abs/2202.09368) 每 expert 從一組 tokens 選固定容量、每 token 可到 variable 數量 experts。其 FFN 被選輸入仍可為該 token x，一旦真實 selection/alpha 已知，不能以此否定共享 P；但不能假設固定 K 或由當前 token 局部選擇可知其真路由，需計入群組決策及容量造成的依賴。`K=1` 雖可計算 P，沒有跨 routed experts 分攤投影的機會。這些均為有條件的泛化界線，不宣稱其是目前 checkpoint 的情況。

## 靜態儲存尺度：H=2048 的 256 KiB map 不是通用尺寸

假設每個 routed layer、expert、leaf 都各存一個 W8 `H×r` dense map，`C=32, r=128` 固定、每係數 1 byte、沒有 dedup/壓縮；flash maps = `L_routed·E·C·H·r` bytes。這是代數上的格式帳，並非支持 256-KiB 模型或 checkpoint-specific 誤差率。若 F32 每 output row 一個 bias 和 scale，各再加 `4·L_routed·E·C·H` bytes；scale 可採其他格式時須重算。若每 layer 保留 F32 shared `P_l`，另為 `4·L_routed·H·r` bytes；centroids、tree、路由、host cache、原始模型、KV、ECC/spare、格式與對齊尚未包括。計算全部 views 並不假定其都需放 host；須對實際放置分別記 flash 與 host。

- 對上列 **DeepSeek-V2-Lite** H=2048、26 routed layers、E=64：每 map 256 KiB；full maps 13 GiB；F32 bias 及 per-row F32 scale 各 0.40625 GiB；F32 P 26 MiB。這只是格式例子，不能排除具體 deployment 對 bias/scale 使用其他精度、分區或共享。
- 對上列 **DeepSeek-V3** H=7168、61 layers 其中 3 layers dense、58 routed layers、E=256：每 map **896 KiB**；full maps **406 GiB**，F32 bias 與逐 row F32 scale 各 **12.6875 GiB**，F32 P **203 MiB**。這些數字沒有加原始 expert weights、shared branch、其他 model weights 或 cache。以 AiF 論文的 1 TB TLC 規模、理想假設所有 cell 僅用 1/3 邏輯頁作 LSB 計算，理論 LSB 上限約 333.3 decimal GB＝310.4 GiB；僅 406 GiB maps 即超出，且實際可用容量更受保留、格式與耐久機制影響。這不代表所有更大 SSD 或其他 representations 都不可能；它只否定把該部署格式無條件推廣到這個公開 V3 配置。[AiF be-enc 原文 §4.3](https://doi.org/10.1145/3695053.3731073) 說 IFP 僅用 LSB。
- 若按**假設**將單 V3 map 均勻分四 chips，則每 chip 224 KiB；每 chip 四個 16-KiB planes 給出 64-KiB/完整 wave 的理想假設下，下限 `ceil(224/64)=4` waves，與 H2048 對應每 chip 64 KiB、1 wave 的算術不同。物理合法地址、row packing、命令、input/FIFO、ECC 與 PE 服務均未驗證，實際只能更複雜；不能用 byte 比例直接作延遲預測。

P/tree 可被共用，不意味全部 metadata 或 maps 可被共用：H、E、r、C、layers、precision、host memory budget、router活躍數、平面映射和原模型/回退是否常駐都控制可行性。兩個 H=2048 checkpoint 即使最終測到良好品質，也不能證明其他 MoE 的品質、可部署容量或加速成立。
