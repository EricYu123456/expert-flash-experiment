# AiF 普通讀取、MoE 與硬體邊界：來源研究

此檔是持續中的 source ledger；時間為 UTC。原文已揭示、作者假設與本研究推論分開。沒有執行候選數值實驗。

## 2026-11-02 19:00 UTC — 起始查核

已讀專案 README、`aif_model_notes.md`、`ordinary_read_placement_candidate.md`、兩份 2026-11-02 研究紀錄；既有強控制包含標準 hypergraph declustering、獨立 phase rotations、複製與相同 allocated-capacity witnesses，以及 SLIM 批次 read-once 的理想資源下界。現有數字為特定模型／配置的模擬，不構成論文的最終系統結果。

* [AiF ISCA 2025 原文](https://doi.org/10.1145/3695053.3731073)：普通讀取每頁有 precharge/evaluation/discharge；cr-read 需同 block 連續無間隔讀取。論文的 6.4 GB/s/chip 與 cr-read、be-enc 有關，不可直接當成所有普通讀取序列的實得吞吐。TLC single-sense LSB 釋出的兩個 page latches 用來放 input vector；權重先 ECC 後經 INT8 multipliers／adder tree。文中沒有公開 MAC lane 數、內部 bit-serial 形式、任意 partial sum 持久化、額外輸入 contexts 或已解 ECC 權重緩存能力，因此都不是免費現有能力。
* [FLINT 2026 §2.2、§4.1](https://arxiv.org/html/2608.25062v1)：作者提出 HBF 每 plane page buffer／cache buffer 交替，在頁資料 drain 時 sense 下一頁；request 合併是 runtime burst controller，已否定「首次利用既有 buffer 讓 sense/drain overlap」的廣泛新穎性。其兩 buffer 和路徑是 HBF 設計假設，不能直接推導 AiF 已有空餘 latch、buffer→PE 連線或重疊時序，也不能將外部 HBM drain 等同 chip 內 ECC／GEMV。
* [SLIM §5.4](https://arxiv.org/html/2507.09201v1)：PE 使用 output stationary、input SRAM 保存批次，權重一次 fetch 為多個輸入服務；因此 read-once batch GEMM 本身已有先例。其 PE 位於 flash controller，具 input SRAM，並不證明 AiF 的原生一 input／latch 支援。

## 2026-11-02 19:03 UTC — Exact-zero 候選的直接 prior 與 NAND plane 邊界

* 更完整重讀 [SLIM §5.1、§5.4](https://arxiv.org/html/2507.09201v1)：PE 除 FMC 外也可配置於 NAND die；sparsity predictor 結果控制權重地址及僅處理有效 neurons，output SRAM 緩存 partial sums 並做跨 PE reduction，文中亦涉及 MoE。它用預測器及可能近似，並非 post-A8 exact zero；但「die 内 sparse weight fetch＋partial-sum SRAM」並非空白。前節將 SLIM PE 簡述為位於 controller 不完整，此處修正。
* [Ripple §4.1](https://arxiv.org/html/2410.19274v1) 已顯式綁定 Llama2 gate/up/down 的相應 neurons，並用 coactivation 重新排列 flash 中相鄰 neurons；不應把同 permutation、共啟用 placement 當首創。它基於稀疏／預測及 SSD→DRAM 流量，沒有核實 post-A8 exact-zero 及 AiF die 數位 PE 的逐 page 契約。
* [SpQt](https://arxiv.org/html/2511.04477v1) 將 quantized weight layout 配合動態 activation sparsity；[SpAx](https://arxiv.org/html/2610.02598v1) 結合 zero/near-zero skip 和較低精度近似並對 flash offload 測試。不是 AiF 可直接複製的電路，但「quantization＋activation sparsity」及「skip zero columns」均須強對照。
* [Micron 公開專利 US10877696B2](https://patents.google.com/patent/US10877696B2/en) 說明傳統單 die state machine、multi-plane 受限，以及獨立 plane 狀態機的設計。這是特定專利的技術陳述，不證明所有現代產品相同。部分 plane 不讀可省感測能量；若同期其他 plane 還要讀，該輪 wall-time 不一定縮短；獨立重疊不同工作需明示額外控制及位址限制。
* [Micron 64/128/256 Gb 型號 datasheet](https://community.nxp.com/pwmxy87654/attachments/pwmxy87654/t-series/215/1/Nand_flash_256Gb_latest.pdf) 的 00h-32h 逐 plane queue、00h-30h 啟動所指定 planes，同一資料表也列有 cache-read。該歷史器件不等同 AiF 所用 NAND；需要檢查特定 page／block 對齊限制，不能假設任意獨立 GEMV streams。
* Exact W8A8 down 稀疏提案的判據：完整 SwiGLU 完成並求 global amax 後取得 integer activation；與同一量化基準比較，零乘積略過可保持整數精確。必須有實際 token／expert 的 whole-page 或 whole-wave 共零數據，並計入 mask 建立、page addresses、ECC、input 配置與 I32 累加器／讀寫仲裁、輸出還原；在無全 plane wave 減少時，僅以跳過的 page 個數推斷延遲收益不成立。

## 2026-11-02 19:08 UTC — 低 tR 物理證據及第一正式候選的最強近鄰

本次第一正式候選於 19:07:01 UTC 啟動：以共用投影 sketch 估算多個 active expert 的 down residual 合成誤差，選擇是否讀低 4 位 residual pages。30 分鐘思考至少至 19:37:01；本項不含 onboarding。尚未執行任何候選數值實驗。

* [AR²／PR² ASPLOS 2021 §5](https://arxiv.org/html/2104.09611)：160 顆實體 3D TLC chips、每 chip 120 blocks、共 3,686,400 WL；作者量測單獨縮減 tPRE/tEVAL/tDISCH 對錯誤影響。文中 2K P/E／一年 retention 下，於其 ECC margin 和 final retry 條件，各自可縮 47%／10%／27%，並報對測試條件 tPRE 至少縮 40% 可使 tR 省 25%。**限制：**其 ECC 72 errors/1KiB，使用 final retry 近最佳 Vref；AiF be-enc LSB 的 ECCLite 只有 10 errors/1KiB。未找到可直接移植 AiF first-read 的 raw error maps；不能把 25% 當作本案可正確使用的折扣。§5.2.2 指 precharge 與前次 discharge 相依，單項收益不可相加。不同 P/E、retention、溫度也改變 ECC margin；AR² 本身已是強精確基準。
* [WISE/WISER](https://www.sciencedirect.com/science/article/pii/S1383762122000054) 已按 DNN weight-bit significance 改 MLC NAND 狀態、保護重要 bits、改善速度，屬模擬；[EASE](https://doi.org/10.1145/3747298) 也按 DNN layer 靈敏度、high-order/residual bits 調整 NAND 儲存與容錯。NAND [US20200057561A1](https://patents.google.com/patent/US20200057561A1/en) 描述按 AI weight importance 施完整／部分 ECC；[US20200117539A1](https://patents.google.com/patent/US20200117539A1/en) 將相同 significance 聚成 bit streams 並採不同 ECC strength。這些是先例，不是已在 AiF 量測的實作或法律分析。
* [US20230280976A1](https://patents.google.com/patent/US20230280976A1/en) 描述依 partial sum 控制後續 memory reads 的低 precharge、短 sensing 或跳讀。實施例列 RRAM/MRAM/DRAM/PCRAM，未明示 NAND flash（搜尋到的 NAND 是邏輯閘）；沒有本案 NAND 時序量測，但其一般概念已公開。
* [SOML ASPLOS 2019](https://www.cse.psu.edu/hpcl/docs/2019_ASPLOS_chun.pdf) 在不同 blocks 並行 sense partial pages，非單 string 的多 WL 類比加總；需額外 select transistor layers、複製 page decoder、拆分 block decoder，作者對 quarter-page 估 die 面積至多 1.7%。shared bitline／decoder 的衝突必須建模。
* [NITRO §III–IV](https://arxiv.org/html/2608.11920v1) 為 analog TLC NAND bit-serial 加 ADC，借 DRAM-PIM 暫存 activations、做 attention 並用多 plane mapping；非 AiF 數位 PE 的現成功能。作者因假設 variation 可比先前研究而省略 accuracy 測試。
* [DPA-MoE §4、Appendix B](https://arxiv.org/html/2610.21378v1) 是核心強基準：progressive expert bitplanes、離線誤差 LUT、線上 per-token routing gate 加權分配 bits；作者明列未考慮 cross-expert residual interaction。其 Qwen3 在統一 precision 時，跨 dispatch exact 與 diagonal error 的 Spearman ≥0.999，但這不是固定 token 下不同 precision subsets 的排序，不足證明 subset cancellation 不可用。要量實際 per-token diagonal oracle、DPA LUT、signed subset oracle；該 prototype 在 matched budget 亦有 TPS overhead。
* [MoBiQuant](https://arxiv.org/html/2602.20191v1) 已有 base＋progressive residual slices 和 per-token router；[Channel Selection](https://arxiv.org/html/2610.37386v1) 以 ternary sketch 估 gate/up activation，再依 router 加權選 channel 並用 low-rank recovery。後者 17.8% 為 logical routed bytes、98.1% 為九組 benchmark 對完整模型準確率的平均相對比例，不是 AiF 的 NAND tR、page/wave 或完整模型延遲。

## 2026-11-02 19:13 UTC — 正式候選的估計器及強基準程式稽核

* [DP-LLM NeurIPS 2025 §5.1](https://arxiv.org/html/2508.06041v2) 已有完全相同的單矩陣技巧：預計算 `G=A ΔW`，runtime 計 `||Gx||` 估低／高 precision 的輸出誤差，再與 threshold 比較決定精度；不是首次提出 projection 或 dynamic bit selection。[作者 code](https://github.com/SNU-ARC/DP-LLM)，read-only clone `/tmp/terra_dp_llm` commit `ad7b8964bc69777311c69e4ed44fb1733f9d66c8`，檢視 `3_save_estimator.py`、`DPLLM_Linear.py`、`DPLLMForCausalLM.py`。每 `(layer,module)` 新抽 Gaussian `A`、`err=(w_h−w_l).float()`、`G=(A@err).half()`；預設對每個 `G` 用 input 及 error norm MSE 作 SGD；執行時該 metadata 按 model dtype 載入、在目前預設 FP16 `Gx` 求 norm 與 threshold 選 bits。此 repo 的 architectures 是 dense 與 CUDA AnyPrecision，沒有確認原封支援 AiF/W8A8/MoE；要依來源定義寫專用 adapter，不可將其 timing 當 AiF timing。
* 可將 DP-LLM 直接概念移植至每個 expert 的 post-GU 私有 `z_e`，作 `||G_e z_e||` 並結合 live gate 作單 expert selector。原 code 各自抽 A 且各自調 G，**G 的坐標不共通，不能把不同 experts 的 vectors 相加計 cross term。**第一候選須約束同層共用投影、保留 signed projected coordinates；finetune 後是否仍可同基底表達需要另設契約與驗證。若值只為 norm 優化，不保證內積和方向。
* [BASE §3.3](https://arxiv.org/html/2609.36222v1)：在 Qwen1.5、DeepSeek V2 Lite、Qwen3 三模型的全 expert 輸出，以 batch=16、固定 M=12，比實際 additive selection 與 exact cross-term greedy，95th error ratios 分別為 1.018、1.025、1.032；不是 4bit residual 也非 exhaustive subset optimum，不能作直接否證，卻要求同 token 的 diagonal oracle 與 combined oracle。
* [BEAM-MoE](https://arxiv.org/html/2512.17073v1) 已用 experts 的 low-rank quantization error 補償，並按 live router score 選擇補償專家；其 per-expert 不同 SVD basis 非同一輸出共同子空間證據。[SPEAR](https://arxiv.org/html/2606.11244v1) 對 token-dependent quantization error 做低秩動態補償。**未知：**所測 G4／DeepSeek 實際 INT8 high/low nibble residual 會否在 experts 之間共享可有效復原的輸出低秩子空間，不能由這些不同格式的結果推斷。
* 相同 metadata 的直接修正是必要強基準：若設共同 orthonormal `U`、`C_e=UᵀΔW_e`，已有 `C_e z_e` 時，除估計外可用 `U Σ α_e C_e z_e` 近似修正輸出；U 的來源、大小、讀取及投影耗時須支付。若多專家誤差近乎各向同性，rank 受限的近似修正也可能無效，須保留為實證問題；如果有強共享低秩，則不能只比較「只用 C 作選擇」與完全不利用 C 的弱基準。
* [Hardt–Woodruff STOC 2013](https://arxiv.org/abs/1211.1056) 證明重複回應適應性輸入時線性 sketch 可失效。對固定且獨立於隨機 `S` 的 `K` 個 residuals，可對所有 `2^K` subsets 使用同時界；但生成 token／先前 layer 的決策可能依賴已重用的 S，不能無條件套固定向量 JL。建議額外獨立 sketch 或 full-error heldout 稽核，明確限定保證範圍；固定多次使用的獨立驗證器如結果反過來影響選擇，同樣有 adaptivity 問題。

## 2026-11-02 19:17 UTC — 多 token 推測驗證與 activation LUT 廣度搜尋

* [DraftExpert §3](https://arxiv.org/html/2607.24434v1) 已將 offloaded MoE 的目標寫為「accepted tokens per newly loaded expert」，用 confidence 和預測 target expert-set expansion 動態截短、prefetch；作者報告包括 Flash→NPU 實驗和 frozen target verification。其 cost 是 expert movement，非 AiF 的 NAND plane-wave／PB／ECC 資源；要以此作思路接近的對照，且不可將換成 waves 的一般代價替換直接稱為新演算法。
* [Speculative Decoding for MoE: Expert Bytes, Kernel Bandwidth and Best Draft Length](https://arxiv.org/html/2610.34440v1) 已從 acceptance 與任意 step time 推導 horizon；測量 kernel bandwidth 與 dedup/reuse 的 crossover，指出少讀 bytes 未必更快。其理論假定 geometric acceptance、route stationarity 與零 drafter cost，且不是 NAND in-flash；真實系統需實測 drafter 與不同 horizon 的非獨立 acceptance、channel/compute/staging 限制。另一篇 [Why Speculative Decoding Works Better](https://arxiv.org/html/2610.38981v1) 對真實模型量 draft tokens routing overlap；不能聲稱首次把 route overlap 算進 spec 成本。
* [S2-MoE §4.2、§6.2](https://arxiv.org/html/2608.15018v1) 基於 verifier route 注入 bias 促使 expert reuse，作者明言是 target-routing approximation；不能把其速度數字稱為與原 target 完全相同的輸出。標準 exact speculative sampling 有特定的 acceptance / correction [ICML 2023 原論文](https://proceedings.mlr.press/v202/leviathan23a.html)。DraftExpert 的 Algorithm 1 先取得候選再根據 confidence/route 決定截斷；若停止條件依抽出 token identity，證明還須處理條件 proposal 分布。該論文所述未完全展開 stochastic correctness，這是須釐清的契約，不是宣稱其實作必有錯。
* [AiF §4.4](https://doi.org/10.1145/3695053.3731073) 的 be-enc 保留兩個 16-KiB input latches。小模型單一 W8A8 vector（例如 1536B）小於它們的總容量，邏輯空間可能可放多個驗證輸入；但多 input address/mux、權重 latch 重讀、ECC 後資料暫存、獨立累加器與在下次 sense 前處理全部向量的時序均未被 AiF 證實。單純容量容得下不表示原生多 context。
* [LUT-NN MobiCom 2023](https://www.microsoft.com/en-us/research/wp-content/uploads/2023/09/LUT_NN_2023-3.pdf) 已對 activation subvector 搜尋 centroid，預算每 centroid 與定值 weight 的 partial outputs，讀出後做 INT8/16/32 加總；其訓練及 codebook search 應作最近的近似計算基準。[MADDNESS ICML 2021](https://arxiv.org/abs/2106.10860) 使用決策樹编码及查表累加；[US20250005365A1](https://patents.google.com/patent/US20250005365A1/en) 也描述 centroid×weight 預計算／lookup。上述不等於實際 NAND/AiF 實作，也不支持 generic activation LUT 的新穎性。
* LUT 的一個 geometry 反例，而非全局下界：G4 down 為 `H=1536, I=512`，`g=16,C=16`，每 centroid output 用 2B；每 group 選一條 3072B output，若各 group 獨立頁，32 groups 產生 32 次 16KiB page sensing、四 plane 8 waves；同 chip 同規則的 INT8 dense 12 waves，INT4 dense 6 waves。表 payload 是 `C*b/g=2` 倍 INT8 權重，還沒算 page padding／ECC／codebook；跨 groups 共頁、對選碼分布設計 layout 或 SOML 可改結果，所以此例不是任意 mapping 的下界。品質應比較同精度／容量的 INT4 與多 seed tasks，不能將「近似」解釋成 bit-exact。


## 2026-11-02 19:23 UTC — activation lookup closer priors, conditional information budget

- Shurui Li et al., **Bit-serial Weight Pools**, MLSys 2022, §3–4, https://proceedings.mlsys.org/paper_files/paper/2022/file/b6856f264cd38f1d8f01d7769be62444-Paper.pdf : offline weight-pool × activation bit-vector dot-product lookup; input-oriented table layout; prefetch only active blocks from flash to SRAM. Its 2024 PhD thesis reproduction https://nanocad.ee.ucla.edu/wp-content/papercite-data/pdf/phdth14.pdf §6.4.2 is MCU on-chip flash, not NAND page-level sensing, and uses shared weight pool + bit serial, not MoE activation PQ. Nonetheless directly invalidates novelty claim that offline dot-product LUT + flash storage + active-table layout is new.
- **LUT-LLM**, FCCM 2026 https://arxiv.org/html/2511.06174v2 §§II–IV and https://github.com/LUT-FPGA/LUT-LLM : activation-only VQ explicitly constructs offline weight × centroid tables, then upgrades to joint weight+activation VQ to reduce table storage. Offline tables indexed by pairs of centroids; online retrieves activation-specific table row and expands using per-output weight-code indices; FPGA-specific code/search/2D lookup/accumulate incurs real bandwidth and search costs. Not NAND or AiF, but prior art + strong capacity control.
- Simple information accounting: g=16, C=16 means activation centroid index encodes 4 bits per 16 elements, or 0.25 bits/activation **before** scales/side information, whereas W8A8 reference is 8 bits/element. Table storage C*b/g = 2 times W8 for b=2 bytes (4 times W4), before padding, ECC, and centroids. This is not evidence of actual quality failure (activation distribution and output sensitivity matter); it shows why claiming W8A8-comparable quality needs rigorous calibration and end-to-end validation. Co-VQ offers a prior-art storage control but adds weight quantization, index reads and expansion.
- **Contrast Calibration** https://arxiv.org/html/2610.20353 §3.3, App. B Eq.32: offline per-expert joint gate/up activation and down weight perturbation error includes their cross term; fixed whole expert configuration allocation across calibration folds. It is not evidence of online same-token *between-experts* combined signed residual sketch selection. Most cases evaluated have shared expert and fixed-input local proxy; full end-to-end model is separately evaluated.

## 2026-11-02 19:24 UTC — speculative multi-token flash reuse prior

- **BigMoMo** current v2 https://arxiv.org/html/2609.14643v2 §3.4–4.4: target MoE verification gathers expert requests of multiple draft tokens, reading each shared expert once, then groups ready experts to overlap UFS–DRAM–VTCM traffic with NPU computation. It explicitly combines acceptance-aware tree pruning, profiled hierarchy-dependent expert selection, on-flash reorganization, batch scheduling. Stronger direct prior than DraftExpert for generic speculative MoE + flash; its flash setup is offload, not near/in-flash MAC or page-buffer reuse.
- §4.2 states expert pruning changes the target expert mixture, so the *full* method is approximate. Its Table 4 distinguishes no-pruning, node-only and node+expert: Qwen3-30B GSM8K norm TPOT 1.00, 0.82, 0.77, respectively; these are measured mobile UFS/NPU, not AiF estimates. Node-only can be used as target-computation control, but distribution-exact sampling still requires checking how pruned proposals are sampled/verified; equal benchmark scores are not a proof. Dynamic flash swaps incur NAND writes/wear; reported §5.4.2 13.42 MiB per generated token, without assuming ordinary AiF relocation for free.
- **LLM in a Flash** https://arxiv.org/html/2312.11514v3 Table 3 combines flash offload and speculative decoding even earlier for dense LLM. Thus novelty cannot be claimed merely for using speculative verification to improve flash traffic. Boundary that remains to substantiate: physically retaining and correcting sensed weight pages while applying multiple independent in-flash inputs, meeting per-token GU/nonlinearity/amax dependencies, and optimizing accepted tokens per real NAND critical path against strong page reuse batching and BigMoMo adaptation.

## 2026-11-02 19:26 UTC — frontier strongest prior; gate-first A8 certificate initial audit

- **FASER** https://arxiv.org/html/2604.20503v1 §4.3 labels its design a frontier: target verifies chunks, commits accepted tokens immediately, resets on full-depth true rejection, overlaps drafting and verification; chunk size optimized using draft/target latency. §6.4.2 evaluates a Qwen2 MoE target on two H100 GPUs. §4.2 separately predicts rejection with intermediate top-K, admits false early exits; do not identify that approximate prediction with actual full-target rejection. Adapt its exact chunked mechanism and use whole-cohort/early-layer-stage baselines; no disclosed NAND-PB page lifetime model.
- **FlowSpec** https://arxiv.org/html/2507.02620v2 §3.1–3.3 segments token tree in score/topological order, executes segments in model-layer pipeline, sends first completed full-target logits back and prunes invalid token/KV at all stages. Segment length is hardware constrained. Code https://github.com/Leosang-lx/FlowSpec. **WaveFront Decoding** https://arxiv.org/html/2609.23033v1 co-batches wavefronts at different depths and verifies earlier ones, but recurrent layer weights are shared, unlike ordinary separate transformer layers. Patent https://patents.justia.com/patent/20260259737 chooses pipeline/batch/token dimensions based on predicted invalid tasks and lists NAND as a generic external memory option, without disclosed AiF PB mechanics.
- Page-lifetime accounting for frontier: with P pages of an expert on one plane and only one weight data latch, after advancing an early cohort through the matrix at most the final page survives for a later cohort (and none if that plane senses another page). Local two-cohort expected extra logical pages relative to processing union once is p|O|−(1−p)|U|, where O is pages shared by both cohorts, U appears only in suffix, p is accept probability. Conditional scheduler observations, 4-plane makespan, later expert routers, and retained page invalidation change the real result; this expression is an illustrative page-count identity, not a latency model.
- Formal gate-first candidate starting 19:26 UTC: after complete gate, evaluate a witness subset of up rows and get max L; precompute per-row ||w_i||2, obtain U_i=||w_i||2 ||x||2; strict |SiLU(g_i)| U_i < L/254 proves rounded full-vector maxabs A8 value zero, assuming exact real arithmetic/half-away rounding. ## 2026-11-02 20:03 UTC — ordinary-read command and buffer feasibility (follow-up to round 1)

- **Stock disclosed AiF:** [AiF §4.4–5.2](https://doi.org/10.1145/3695053.3731073) describes the chip GEMV request as vector dimension, block ID, page offset, and number of sequential pages. Every described request loads the input into page-buffer latches, reads sequentially, corrects each weight segment by ECC, computes, and drains final outputs via an on-chip FIFO polled by the controller. The paper reuses one or two of the remaining latches for *one* input vector; it does not disclose arbitrary sparse page lists, cross-command vector lifetime, a bitmap command, output-accumulator re-entry, or a raw-I32 FIFO output mode. No CR-read is necessary for sequential ordinary reads, but each selected page still has to be sensed.
- **Controller/software-only design to investigate:** partition selected Up pages into physical block- and chip-aligned contiguous runs and issue one disclosed chip GEMV per run; scatter final row outputs to their logical destinations. This requires a concrete page/row mapping and preserving full rows, but needs no hypothetical sparse-list chip decoder or cross-command input retention. Existing commands reload the input every run under the published flow; host-to-controller input staging and controller-to-chip fan-out are separate transfers, so one must charge all actually repeated copies and channels. More commands/status polling and the Gate/witness-to-mask dependency have latency. The source does not specify numerical command setup time, and no latency benefit may be asserted just from fraction of rows skipped.

A single bitmap/list command additionally needs storage for list or bitmap, a page-address iterator and end/status behavior. Different choices change the hardware bill and must be modeled separately. For a finite binary page sequence of length P with m selected pages in a single contiguous physical region, the number of runs is at most min(m, P−m+1); block/chip boundaries add splits.

- Causal phase accounting is at least: Gate and paid witness computation, output arrival/host synchronization, actual activation and lower-bound formation, host access to bound metadata and certificate evaluation, mask-to-physical-run translation, selected Up reads plus vector reloads, A8 completion, then Down. Independent stages can overlap only when the proposed dependency graph and resource ownership permit; compare an equally equipped baseline and a normal full-GU route that need not wait for the certificate. Original-order 16 KiB logical masks in the frozen stage-0 protocol are opportunities, not measured plane waves, NAND timing, or wall-clock speedup.

- [SPICE §4.2](https://arxiv.org/html/2608.21240v2) fits one low-rank output residual `B_e A_e h ≈ E_e(h) − S(h)` per routed expert from target-model traces, retains original experts, and at runtime uses `S(h)+B_e A_e h` on a low-confidence miss while using original expert execution for an unsuitable substitution. This is a direct original-plus-extra-surrogate-bank and fallback precedent. - A **new proposed strong control derived from SPICE**, not a claimed SPICE implementation: for a pair `(i,j)` execute original `F_i(x)` plus pair-specific low-rank correction `D_ij(x)=B_ij A_ij x` fitted to `F_j(x)−F_i(x)`. Approximate the weighted contribution as `(alpha_i+alpha_j)F_i(x)+alpha_j D_ij(x)`. Keep all E originals for unmatched cases and M overlapping low-rank corrections; no native shared expert is required. This tests whether dedicating a full extra student to each edge is necessary. In real arithmetic the α dependence is affine by construction, but the learned residual is approximate, quantization and execution order must be specified, and quality is entirely unknown.

Each `A→B` incurs sequential phases, vector transfer, possible host memory traffic and page/chip padding. Do not present coefficient ratios as realized area, sensed waves, quality or latency; equal-byte and equal-quality matching is mandatory.

## 2026-11-02 20:57 UTC — pair-bank focused review, judgment and falsifiable gate

- **Judgment:** current overlapping pair-bank is an expensive synthesis of substantial established mechanisms, not yet a demonstrated paper contribution. [NimbleMoE §§3.1–3.3 and Appendix D](https://aclanthology.org/2026.emnlp-main.2036/) already has original router weights, coactivation clustering, shared-basis compensation, and maximum-weight perfect matching for fixed pairs. [CRISP §§2.2, 3.2–3.3](https://arxiv.org/html/2610.37442v1) already makes pair-conditioned E-only precision/width choices. [SPICE §4.2](https://arxiv.org/html/2608.21240v2) already stores surrogates alongside original experts and conditionally falls back. [KDEM §4.1](https://proceedings.neurips.cc/paper_files/paper/2025/file/201e1777dfabe595d766d5222f20f2dd-Paper-Conference.pdf) distills live-router-weighted multi-expert outputs into a parameter-merged student; [IntBMoE §§4.2, 4.7](https://arxiv.org/html/2609.21346v1) describes caching a finite set of composed expert blocks. None of these inspected sources establishes precisely E full originals + M overlapping post-trained pair-output views with dynamic top-K disjoint matching and original fallback, but that distinction alone does not establish practical novelty or superiority.
- One **bounded falsification question** is worth considering: at the same total flash-byte budget and matched held-out output/task quality, do overlapping pair views yield fewer physically scheduled NAND sensing waves than fixed pair views or E-only pair-aware execution, with the same observable router and matching decisions? The question is about a quality–capacity–sensing Pareto improvement, not merely the existence of overlapping edges or a higher oracle route coverage. Recommend an experiment only if its protocol commits to meaningful matched controls and a predeclared stop rule; otherwise preserve the remaining formal experiment opportunities. Even a positive small local screening result is not a publication or deployed-speed result.
- A discriminating protocol would use disjoint calibration/held-out prompts and the same selected teachers and live alpha across comparisons; factorially compare fixed versus overlapping bank topology with the same view representation, and identical topology with full pair student versus Nimble-style shared basis, a single-original conditional representative, and the SPICE-inspired pair-specific low-rank correction proposed in the prior 20:53 entry. Include CRISP-style E-only width/skip and W4 original experts as independent strong Pareto comparators, with the same calibration effort and practical rounding/quantization semantics. Account for *all* originals, extra views, correction matrices, scales, alignment, ECC and physical padding in total capacity; charge sequential A→B phases, transfers, chip imbalance and all commands in physical waves or latency. Training loss alone is not proof of end-task quality.
- A graph matching chosen using true teacher-pair errors unavailable until the two original experts have already been read is an **oracle upper bound**, not a deployable scheduler. A deployable policy must use only information actually available before the decision, such as selected IDs, live router weights and an offline-calibrated edge score, and pay the timing of that decision. Confidence/fallback must likewise specify how it can be assessed before reading expensive original outputs. Live-alpha incorporation before dynamic A8 rounding is not automatically numerically equivalent to weighting independently quantized expert outputs; specify exact student arithmetic and compare it to the frozen reference.
- The publicly posted [IntBMoE implementation](https://github.com/AMAP-ML/DreamX-Rec/blob/main/intbmoe/core/block_moe.py) composes blocks in `forward`; the paper's inference cache is a stated system design, not an already reproduced cache implementation in that code. The [PCoMoE author repository](https://github.com/gzyyy0/PCoMoE) is README-only at this review, unlike [PuzzleMoE](https://github.com/Supercomputing-System-AI-Lab/PuzzleMoE) and [MoE-Quant](https://github.com/IST-DASLab/MoE-Quant). This is a source audit, not a claim that prior paper findings are invalid.
