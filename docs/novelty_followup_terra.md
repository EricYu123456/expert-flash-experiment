## EBC: author notebook, actual function and runtime

- Original public repository [Expert-Bank-Compression at commit aa323a40cd0ecd280102fa29377ec816177f4a6c](https://github.com/danishberg/Expert-Bank-Compression/tree/aa323a40cd0ecd280102fa29377ec816177f4a6c); [notebook permalink](https://github.com/danishberg/Expert-Bank-Compression/blob/aa323a40cd0ecd280102fa29377ec816177f4a6c/ebc_paper_calculations.ipynb). Previously downloaded local snapshot is `results/research-2026-11-03-no-cr/prior-sources/ebc-author-code/ebc_paper_calculations.ipynb`, SHA256 `069749a1883ada122da93f27c6106fa84c668d9a1289beeaf63d4b886415f102`. It contains 49 cells and several successive versions. Detailed audit below uses cell 46; a shallow AST scan found 19 cells defining `apply_expert`, all containing a `cluster_of_pos` lookup and `random_proj_features` on `Ws`. That simple scan is not a full semantic review of all notebook versions or the IEEE article.
- **Target and calibration** — `forward_mlp`, cell 46 lines 755–760 computes each teacher expert's `down(silu(gate(X))*up(X))`. `build_Ws`, lines 774–895, loads calibration X and fits one **H×H linear** operator W per expert against those expert outputs, optionally weighted with router probabilities (weighted mode default false at lines 180–187). It uses ridge damping, a least-squares solve, and optional Frobenius normalization; no intercept is appended in this inspected path. Calibrated inputs can be captured from a model hook (lines 562–734); this capture uses forward passes with `use_cache=False`, and repeats chosen text across batch/iterations. If calibration is missing or NaN, source has a synthetic random-normal fallback and a uniform-router fallback, lines 798–819. Which configuration produced any specific published/social number is not established by these code paths alone.
- **What is clustered** — `random_proj_features` lines 1056–1066 takes Ws shaped `[E,H,H]`, computes per-expert row/column energy features with a random projection, then `main` lines 2107–2121 runs K-means and cluster balancing on those **experts**, not on current token hidden states. The resulting `cluster_of_pos[expert]` is persisted in payload. `OrthoParam`, lines 1138–1148, and `main`, lines 2123–2184, initialize each cluster's orthogonal U,V from SVD of the expert-operator mean and optimize block/diagonal energy/sparsity objectives. They are per-expert-cluster shared **full H×H** bases in the inspected implementation, not the proposed one layer-wide H×r input projection.
- **Deployed mathematical form** — `build_payload_for_cluster`, lines 1407–1504, transforms each W into Uᵀ W V, selects per-expert blocks, represents remaining error by shared low-rank factors with expert-specific diagonal/full coefficients, optionally adds residual blocks, and stores the representation. `PayloadRuntime.apply_expert`, lines 1327–1366, chooses a static expert→cluster assignment, applies `z=xU_c`, the expert's structured block/low-rank terms, `V_cᵀ`, and expert scale. `apply_mixture`, lines 1369–1373, consumes live routed experts and gates. This cell is a strong direct prior for replacing nonlinear expert FFNs with fitted full-input operators and expert-group shared transforms. It does **not visibly choose a different operator for an expert by partitioning each input token's state**. That distinction is a finding about this notebook snapshot, not a definitive negative claim about the inaccessible 5-page IEEE publication or all unpublished implementations.
- **Metric separation** — `eval_payload`, lines 1510–1578, evaluates compressed runtime output against `x @ (Ws_norm * Sc)`, the **already-fitted linear surrogate**, on random x. When stored router probabilities are available, x and router trace rows are independently sampled; its reported relative error tests the structured payload vs the linear W, not the original nonlinear expert and not paired hidden-state/router samples. `compute_proxy_error`, lines 1675–1716, is a different calibration-input comparison of a mixture of the uncompressed Ws with captured original block output Y. Router normalization and exact model-specific block output semantics need inspection before treating it as a universal mixture-quality metric. `compute_perplexity_increase`, lines 1908–2077, constructs a model with `num_hidden_layers=LAYER+2`, uses `CAPTURE_TEXT` with max 64 tokens, and returns the framework's original/compressed **loss**; no `exp` is applied in that function. It is not proof of held-out full-model perplexity. The source review cannot establish that the author's public 4.42×, 5.5% or +1.53 figures came from this cell, its defaults, or these metrics; do not relabel or disprove them without the missing experiment/paper.
- **Capacity and runtime semantics** — `compute_expert_size`, lines 343–370, counts selected original gate/up/down tensor elements ×2 for an FP16 numerator; lines 325–327 save `np.savez_compressed`; `main`, lines 2257–2261 divides FP16 byte count by compressed NPZ file size. `pack_blocks_ragged`, lines 1255–1296, optionally stores INT8 per-block values and scales, while `unpack_blocks_ragged`, lines 1298–1321, expands blocks to float32 on the device. Thus this source's compressed file bytes and float32 Python/runtime are not evidence of flash random-addressable payload size, on-die integer decoding, or AiF throughput. Every factor, scale, index, cache line and active read must be charged at its actual deployable precision; equal flash capacity and comparable live compute remain necessary.
- **Fair shared-basis control, derived here** — for experts assigned to a common cluster c, linearity gives `Σ_e α_e s_e ((x U_c) T_e) V_cᵀ = ((x U_c) Σ_e α_e s_e T_e) V_cᵀ` over real arithmetic, where `T_e` includes structured core and residual. In principle reuse each cluster's input transform once and its output lift once for simultaneously routed experts, while charging all selected per-expert T_e, U/V transfer/cache, accumulation, metadata and quantization. The source's direct `apply_mixture` loop does not implement this transformation. Treat it as an optional strong schedule, not an author result; floating-point reassociation is not bitwise exact and per-cluster H×H bases can be expensive. A layer-wide shared P with lower rank or context selection is a separate design that must establish quality and end-to-end benefit, not automatically novelty.

## Flash-Jacobian: accessible Zenodo version metadata and scope

- The official Zenodo API now responds at [record 19150764](https://zenodo.org/api/records/19150764) and [version list](https://zenodo.org/api/records/19150764/versions). Version 19069517, created 2026-03-17, is titled [“Flash-Jacobian: IO-Aware Piecewise Linear Approximation of Large Language Model Layer Dynamics”](https://doi.org/10.5281/zenodo.19069517); its record/abstract explicitly describes input-region-conditioned low-rank best-fit local operators, using Woodbury and 2000 fitted local operators. Version 19150764 is dated March 21 and latest 19324504 March 30. Metadata lists one PDF and no code file in each record. A checked metadata record listing only a PDF does **not** prove code does not exist elsewhere.
- For the initial version, the listed PDF is 1,088,843 bytes, MD5 `9ff000f9e155d1128efaaa9ef8121b6a`; for 19150764, 1,429,949 bytes, MD5 `e93a4b0f0852a250e83abf3440a97aba`. The latter full PDF's §3 calls these population-level fitted input/output operators rather than exact pointwise derivatives, and describes regional low-rank ridge, tiled assignment and sort/inverse grouping. The paper explicitly uses dense language-model layer representation analysis, not demonstrated AiF inference. Direct PDF source: [19150764 PDF](https://zenodo.org/api/records/19150764/files/Flash-Jacobian.pdf/content). I did not identify a verified code repository in this bounded screen.
- The [anonymous OpenReview paper](https://openreview.net/attachment?id=au5FGRgwcZ&name=pdf) shares the same substantive operator construction and title language, but I have **not** verified document identity, authorship link, revision relationship or identical metrics; treat them as separate primary records and do not use any such linkage to infer identity. The Flash-Jacobian technical core already makes region-selected low-rank FFN surrogate and approximate lookup in itself an unsafe novelty claim; the distinct, unproven question is whether co-designing one layer-shared projected key and representation with expert routing, actual NAND ordinary page waves, command/vector constraints and equal host-cache alternatives produces an advantageous quality/latency/capacity frontier.

## Decision implications, not experimental results

A defensible comparison needs expert-specific global full-input ridge/reduced-rank models with contextual biases as appropriate; original quantized-expert W4, live-router and equal-cache controls; Flash-Jacobian-style per-region independent-input low-rank fits; and EBC-style full-input expert-group shared transforms with reuse and real runtime costs. Match calibration/selection budgets, output definition, finite precision, flash/host storage and reuse. Only future measured quality and ordinary-read full-system performance can decide whether the integration overcomes these prior methods and their strong resource baselines. An inaccessible IEEE full text and possible unlisted repositories remain real uncertainty; no assertion of novelty or lack thereof follows from a search failure.
