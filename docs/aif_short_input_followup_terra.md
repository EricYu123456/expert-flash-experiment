# Short-input digital NAND and MVM source follow-up

2026-11-03 UTC. Source reading only: no candidate code or simulator, FPGA/RTL, quality experiment, model or new data payload was run/read. This note supplements [AiF contract audit](hardware_contract_sources_terra.md) and [break-even analysis](../results/research-2026-11-03-no-cr/round02-local-affine/aif_bank_break_even.sol.md); it does not infer native AiF support from neighboring devices or patents.

## Most relevant new primary evidence

### A digital SRAM MVM implementation with explicit row lifecycle

[liamung/mvm-engine, commit 5e6a246a34000a1aa4f5afcacb60bc68ba84e602](https://github.com/liamung/mvm-engine/tree/5e6a246a34000a1aa4f5afcacb60bc68ba84e602) is publicly readable SystemVerilog for a **different, FPGA/SRAM-backed digital MVM**, not NAND or AiF. The author describes it as synthesizable and reports FPGA timing, but I did not run tests, synthesize, or independently verify those claims. No explicit repository license was exposed in the queried metadata; check reuse terms before copying code.

- [`ctrl.sv`](https://github.com/liamung/mvm-engine/blob/5e6a246a34000a1aa4f5afcacb60bc68ba84e602/src/ctrl.sv) latches `vec_num_words`, tracks vector word and output-row counters, asserts `accum_first`/`accum_last`, and resets the vector address for the next row while advancing the matrix address. It demonstrates a concrete row-boundary implementation, not that AiF already has it.
- [`dot8.sv`](https://github.com/liamung/mvm-engine/blob/5e6a246a34000a1aa4f5afcacb60bc68ba84e602/src/dot8.sv) contains eight parallel signed 8-bit multiplications and a pipelined adder tree. [`accum.sv`](https://github.com/liamung/mvm-engine/blob/5e6a246a34000a1aa4f5afcacb60bc68ba84e602/src/accum.sv) uses a 32-bit accumulator and output register: first loads the sum, middle adds, last emits with a one-cycle valid pulse, and the one-word first+last case emits directly. [`mvm.sv`](https://github.com/liamung/mvm-engine/blob/5e6a246a34000a1aa4f5afcacb60bc68ba84e602/src/mvm.sv) delays first/last by six cycles to align its memory read and dot pipeline; it broadcasts one SRAM vector word across configurable output lanes.
- The top-level publishes `o_result` and `o_valid` but no output `ready` or FIFO/full input. The controller does not stop for downstream backpressure. It cannot directly establish lossless streaming into an unknown NAND FIFO or claim safe arbitrary polling delays. A prototype must either add sufficient buffering and credits or propagate stalls to **every** affected valid/data/first/last pipeline stage, or else prove a fixed sink service bound; prove no outputs are dropped, duplicated or misordered. In particular, the controller's `busy` goes low at the end of issuing reads while results are still in the delayed pipeline; define separately *accept-new-command*, *all-pipeline-drained* and *all-results-consumed* semantics.
- The code default has eight output lanes, each with 512 words of local matrix memory; each word represents eight W8 elements. A 128-element row needs 16 such words, hence at most 32 complete rows/lane or 256 across eight lanes if the default memories are dedicated to this row-major mapping. The illustrative 512-output-per-chip case would require a deeper matrix store, additional lanes/memory or a correctly charged streamed/reload schedule. This is an inference from those RTL parameters, not evidence that actual AiF requires SRAM or shares the same limit. The engine does not model NAND page sensing, ECC, page-buffer latch conflicts, flash-plane arbitration, ONFI, or a 16 KiB NAND page.

### NAND page-buffer digital proposals, not native AiF implementations

- [Macronix US20230161556A1, figures 5–6](https://patents.google.com/patent/US20230161556A1/en) describes bitwise logic between page-buffer latches, partial-product accumulation and configurable weighted/unweighted accumulation. One illustrative implementation selects 128 **bitlines/bits per cycle** out of 131,072 and accumulates groups of dimensions into a 512-dimension output; other widths are contemplated. It describes encoded inputs/weights and latch operations with distinct cell/sense/error behavior. This is an intellectual-property disclosure, not an implementation measurement; 128 selected bitlines per cycle does **not** mean 128 independent 8-bit products per cycle, a 128-byte vector command, or selective sensing of 128 bits while the rest of the page costs no array read. It does not show AiF's corrected LSB ordinary-read → INT8 PE datapath or output FIFO contract.
- [YMTC EP4649485A1, figures 1F and 3A–3B](https://patents.google.com/patent/EP4649485A1/en) describes NAND peripheral page buffers receiving input and sensing weight data, a separate processing unit with input/result registers and a controller, and possible FIFO registers for operand segments. It describes implementations with one processing unit per plane or units shared across multiple planes, as well as a six-element example. That topology is useful evidence that plane-to-PE sharing/arbitration is a genuine design choice, **not** the number of AiF PEs or proof of its r128 command. The patent does not specify AiF's accumulator row reset, on-die ECC arrangement, FIFO depth, polling behavior, measured 28-µs total service, or a gate that makes unused bytes free to sense. A patent disclosure shows a possible design, not a shipped device or validated cost.
- [US9678832B2, on-chip copy gather](https://patents.google.com/patent/US9678832B2/en) illustrates an explicit NAND page-data transfer into auxiliary latches followed by a separate sense command for another wordline. Its latch/data-path manipulation is a real documented architecture option, but it is not an AiF GEMV, a 128-byte operand-residency guarantee, or elimination of the sensing operations needed to fill those latches. Page-buffer column selection and arithmetic gating after sensing can reduce data movement/compute; neither alone establishes avoided full-page NAND sensing. ECC granularity and the order of correction vs masking must also remain explicit.

## AiF figure and artifact search

The local paper extract `paper/aif.txt` includes Fig. 14's logical blocks: controller, I/O, SREG, four PBs, PEs, FIFO and ECC. The author-lab publication page points to the [ACM paper](https://doi.org/10.1145/3695053.3731073), but an attempt to retrieve its PDF at the publisher returned HTTP 403 challenge. Therefore **the original vector figure has not been visually inspected in this follow-up**; no lane count may be inferred from the extract or from the number of schematic icons. A bounded search of the ISCA program, author/lab pages, GitHub names, vendor patents and open digital MVM sources did not reveal an AiF-authored PE RTL, short-vector field-width document, FIFO specification, or slide with lane-count evidence. This is a search result, not proof those materials do not exist. [ISCA program](https://www.iscaconf.org/isca2025/program/) confirms the paper's presentation, but does not itself give a PE contract.

## Concrete prototype questions, not an authorization to build or test

1. Specify the command boundary: input element bit width/encoding, vector length units and legal minimum/maximum, byte alignment, page count, output row count, endianness, output value width and scale ownership. Reject zero/unsupported lengths explicitly; show a complete 128-element transaction through input staging, page correction, row-end and output completion.
2. Declare PE configuration and memory mapping: how many signed INT8 multipliers/accumulators are per chip and per plane, operand width, issue rate, lane utilization, vector broadcast, page-buffer bank ports and whether multiple planes contend. Model 128 complete W8 rows per 16 KiB data page only under the stated no-padding/no-interleaving ECC mapping; do not assign zero hardware or traffic cost to padding, codeword boundaries, block scales, or a different layout.
3. Verify integer correctness against a declared software reference using signs/extrema, all-zero input, single nonzero coordinate, consecutive rows with alternating signs, first/last and partial final lane, invalid dimensions, different row counts and page crossings. For full-range signed 8-bit × 128 elements, use at least 23 signed accumulator bits; 32 bits suffice before scaling. Define numerical reference, rescaling, rounding, saturation and bias separately.
4. Insert controllable output stalls, randomize latency and command spacing, and check output count/order and valid/ready behavior until all work is drained. For 16 KiB/128-byte rows, each plane can generate 128 I32 outputs = 512 bytes; four planes can jointly generate 512 outputs = 2 KiB per chip for this particular fully packed page wave. This is total data, not a claim FIFO needs precisely 2 KiB: the minimum sufficient FIFO depends on the arrival/service traces, existing in-flight registers, concurrency and permitted PE stalls. Formally a no-stall queue needs peak positive `arrivals(t) − departures(t)` bytes; an allowed backpressure design may use less but must charge delay.
5. Time the ordinary-read dependency graph with measured or synthesized/verified `t_sense`, ECC service, PE row service, drain, polling, input fanout and command setup. Report overlap and shared-channel arbitration rather than assuming them; the published 6.4 GB/s ECC throughput cannot determine PE MAC/s. For a full single 64 KiB/chip r128 wave, compare the actual `65,536 / sustained_MAC_per_second` with other services; 28 µs is a read component, not an established end-to-end latency. Validate controller-side effects and a baseline with the same legal extensions. Record synthesis target, process, timing constraint, memory macro assumptions and PPA if any; a source-level sketch alone cannot substantiate 'minor hardware change'.
