Complete rows, prefixes and numerical invariants
----------------------------------------------
Deep H=2048, routed I=1408. GU has2816 complete output rows:1408gate+1408up.
Each row is2048 W8 coefficient bytes. A16KiB page contains8 complete rows; a
four-plane64KiB wave contains32. Therefore core160rows=20pages=5waves,
long192rows=24pages=6waves and packet32rows=4pages=1wave. Every endpoint holds
core160 followed by exactly one packet32. A high endpoint's packet is its own
original final32rows; a matched low endpoint holds another physical copy of
those identical32rows. Each edge executes exactly one long and one short
prefix. The short prefix ends at a complete wave: there is no partial row,
unselected computed suffix row, fringe drain/drop or new row-stop instruction
needed in this C2048 construction. Every read job still executes an ordinary
contiguous dense matrix against the entire same H-dimensional input.

The16cores contain2560 unique logical rows. Eight distinct packets contribute
256 more unique logical rows. The physical multiset contains3072 row slots:
2816 original logical rows and256 duplicated slots. It does not contain3072
independent logical rows. layout0_row_ids.json maps every stored slot back to
its original expert/gate-up/logical-row identity. Both source and destination
packet slots reference the same immutable original row scale. Other layouts
have the same inventory and differ in packet destinations.

Full-row numerical equivalence follows under the already fixed W8A8 arithmetic:
retain original full-row W8 bytes and F32 row scales; retain full2048-element
GU input A8 bytes/input scale; accumulate the complete row dot; perform the
same I64->F32 conversion once and same F32 rowScale*inputScale multiplication
once, with contraction off. Scatter each useful result to its original logical
row. Do not re-quantize a packet, scale by physical output index, or infer row
identity from chip-order output rowcounts after moving a suffix. A destination
long prefix usually represents two disjoint original logical-row intervals.
The prior numerical proof established the general complete-row prefix/scatter
primitive on G4; this audit checks Deep symbolic row/scale identity, not actual
Deep coefficient arithmetic or native PE output/scaling format.

All experts still have16positive GU jobs and88waves per view. Each job reloads
its whole input and owns the chip's sole context from command through output
drain. There is no page-buffer weight reuse, extra plane context, partial dot,
mid-command early-ready or activation in flash. After all2816 logical GU rows
of one expert have arrived and been scattered, the host performs SwiGLU and
quantizes the complete1408-element Down input once. Private Down requires that
whole-expert barrier. Router weights, shared geometry and Down remain fixed.

Standard orientation and exact fixed-graph chip-work objective
-------------------------------------------------------------
Each expert contributes a perfect matching on16chips. Six selected experts
give48edges and degree6 at every chip, including parallel edges. Each component
is even-degree, so follow an Euler closed walk and orient each traversed edge
forward. Arrivals equal departures, hence indegree3 at every chip. The pure GU
NAND workload is thus6*5+3=33waves/chip, reaching the average528/16=33. This is
the elementary balanced Euler orientation construction, not a new theorem,
batch code, or claim of worst-case full-FFN latency optimality.

For the fixed native service, changing one prefix160->192 adds one28us read
and128output bytes at2GB/s: delta=28064ns. Commands, full input reloads and
number of jobs stay unchanged. Let F_qc contain all six5wave GU base jobs plus
unchanged Down/shared ownership work. For assignment indegrees d_qc, the exact
chip-owned work objective is max_c(F_qc+28064*d_qc).

For a trial T, add source->one node per selected packet capacity1, packet->its
two endpoint chip nodes capacity1, and chip->sink capacity
  floor((T-F_qc)/28064), clipped to[0,6].
All48units must flow. Integral flow chooses exactly one physical copy for every
packet. This gives an exact minimax chip-work solution for this fixed graph and
uniform incremental packet work. It may use indegrees other than3 to compensate
fixed Down/shared imbalance. Endpoint-specific unequal packet costs, extra
commands, incomplete prefixes or altered output service would require a new
objective and cannot silently reuse this unit-capacity formulation.

Chip-owned work is necessary, not sufficient, for native completion. Controller,
channel and host contention and GU->activation->privateDown causality can add
time and depend on which expert receives each extra. Equal joined-work ns does
not imply equal native service. The earlier coupled-work-contract-audit has
independent ReferenceGraph witnesses. No selector/scatter latency is added here;
zero overhead makes this an optimistic screen, not an executable speed claim.

For the currently frozen greedy executor only, the first logical expert has16
positive GU jobs. The controller dispatches their commands in chip0..15 order,
each250ns, starting at host_submit2000ns. All are dispatched within4us, before
the earliest28us read can complete. Orientation cannot alter those first command
start offsets. Therefore native finish >=2000+max_c(F_qc+28064*d_qc+c*250).
Minimizing that expression with the same flow is a valid stronger necessary
bound for this executor. It is not an arbitrary-scheduler bound.

Known AiF evidence and finite ABI conditions
------------------------------------------
paper/aif.txt:744-749,761-779 specifies input dimension, block ID, block offset
and page count followed by ordinary INT8 dense GEMV. A20/24page prefix needs no
row mask or early-stop feature beyond that ordinary page-count view. The job
shapes160/192 are no larger than the existing192row GU candidate. Native maximum
pagecount bits, max R, exact output format/scaling, FIFO depth/backpressure and
custom row-to-logical-output mapping still are not established by visible code.
paper/aif.txt:818-823 describes sequential FIFO/polling but does not expose those
limits. The2KiB input dimension is below the8-32KiB typical inputs described at
724-743; that typical range does not establish all legal dimensions. The whole
job remains one input context. Cross-block jobs must split (925-928); our
resident jobs do not cross. Host scatter and a controller range table are
software requirements, not evidence that an actual supplied driver supports
them. kernel/aif.h:11 explicitly says metadata only, no weights/GEMV outputs;
therefore the trace/timing ABI cannot certify the native numerical or view ABI.
These are existing ordinary-row-candidate limitations; they do not authorize
inventing a larger buffer, new command, context or new PE behavior.

Primary prior and claim boundary
-------------------------------
Oktay, Turk and Aykanat, Selective Replicated Declustering for Arbitrary Queries
(Euro-Par2009), explicitly optimizes which items are copied and their disk
locations under a replication budget; section2 states that per-query minimax
copy retrieval is solvable by network flow. This directly covers the generic
selection/placement mechanism, without the AiF phase DAG or measured timing.
https://repository.bilkent.edu.tr/bitstreams/938fed97-cc40-48c5-bbd8-01da42e95ae2/download

Bujtas and Tuza, Relaxations of Hall's Condition: Optimal batch codes with
multiple queries (AADM2012,6(1):72-81, DOI10.2298/AADM111130024B), formulates
replicated items as sets of servers and a bounded-multiplicity representative
selection through a relaxed Hall condition. Our balanced matching union is an
elementary application, not a new batch-code theorem.
https://doiserbia.nb.rs/Article.aspx?id=1452-86301100024B

The balanced-orientation proof above is included explicitly so no strong prior
claim relies on a theorem name. We do not attribute native AiF context, output
ABI, GU readiness or a physical performance result to either prior.
