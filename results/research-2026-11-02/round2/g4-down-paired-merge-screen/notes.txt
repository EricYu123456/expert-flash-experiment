Ordinary full-row hardware/numerical contract
-------------------------------------------
Each routed Down has1536rows x512columns. Original B has12positive128row chips
and4zeros. Pair the12positive chips into six directed(source,dest) edges, fixed
offline. Source retains its original128rows; dest stores original128core plus
another physical copy of source128rows. Runtime edge0 executes128+128; edge1
executes0+256. Every edge always executes256unique useful rows and2waves.
Each expert executes1536unique rows/12waves; jobs range12..6. At most one Down
job per expert/chip, full private512-dimensional input every job, one chip
context through output drain. GU/shared remain original B and every private
Down waits for the whole expert GU->host activation->complete-vector A8 barrier.

128x512=65536B=4pages=1wave;256x512=131072B=8pages=2waves. All prefixes end at
full row/page/wave boundaries. Every computed Down row is useful and consumed
once; no fringe, partialrow, partialdot, validR, MAC stop or extra context.
Dest256 outputs correspond to original core IDs followed by source suffix IDs;
scatter/scales must use those original logical row identities. Preserve full
W8 rows and original F32 scale, identical private input A8/scale, original dot
and once-only conversion/rescaling arithmetic. This branch verifies symbolic
row/scale identity and modeled timing, not actual weights or PE output ABI.

Resident per expert=2304row slots:1536unique logical rows+768duplicated slots.
6copies/expert x64 x128rows x512B =24MiB useful/page storage=1536pages/384waves.
These are copies even if stored in prior holes. No resident descriptor with
2304slots is submitted as2304independent logical outputs. Each actual view is
lowered with1536logical output rows. Physical row-ID inventories retain every
original source row and identify copies rather than inventing aliases.

Service and finite work/LP screen
--------------------------------
Original128job=28762ns=command250+fullinput256+read28000+output256.
Merged256job=57018ns=250+256+56000+512. Therefore edge1 changes chip-owned
work by-28762source,+28256dest and saves506ns aggregate command/input work.
An aggregate saving or a lower bottleneck work does not prove causal latency.

32routeblind layouts:16seeded random matching/directions,8random matchings
directed toward lower expertGU+shared work,8deterministic low/high variants.
For every512query, feasible policies use allsplit/allmerged starts and two36bit
greedy passes. Continuous LP for all16384layout/queries relaxes bits to[0,1].
Its reported lower bound is an exact integer dual certificate, not an unchecked
floating solver objective: for any nonnegative integer chip weights w,
  floor((w.base+sum_edges min(0,w.effect))/sumw)
is <= the continuous and discrete optimum. audit_and_addresses.py independently
recomputes all16384certificates with Python integers and all feasible loads.
The float LP optimum is within~1ns of the conservative floor certificate.

Best original greedy graph4:550043.55859375ns work,0.99289373%work improvement.
Best continuous-LP graph15 gives535607.04296875ns work lower bound,4.18677911%
optimistic native mean headroom after host. It is not a fractional execution
proposal. Its large integrality gap motivates the stronger packet bound below.

Stronger integral unit-packet relaxation
---------------------------------------
Keep every destination128core at real cost28762. Treat each source128packet
as one integral28256ns packet assigned to source or dest, waiving source-only
506ns command/input overhead. There are36packet edges/query. For a trial T,
edge->two endpoint integral maxflow with chip capacity
  floor((T-fixed_chip_work)/28256)
is exactly the minimax uniformpacket relaxation. This is standard replicated
job assignment, not a new theorem or actual chip work.

GU never changes and the first logical expert has positive GU on all16chips.
For the frozen canonical priority executor, commands start2000+c*250 before
any28us read completes. Add these chip offsets before the flow and host2000ns
afterward. This is an executor-specific necessary bound, not a scheduler-wide
limit. Every one of16384flow optima was certified feasible atT/infeasible atT-1
with119441SciPy Edmonds-Karp calls. Max remaining mean headroom is2.26512075%
atgraph14; all P99headroom <=0.91969773%.17of32graphs are below2%mean outright.
Source506ns was deliberately waived, so those assignments/bounds were not
reported as actual work.

Restoring real506ns for each source-endpoint packet gives legal split/merge
bits. Two independently evaluated formulas agree for every32x512chip vector:
originalbase+effect*bits, and relaxedbase+28256*packetcount+506*sourcecount.
Graph14 pure restored work=545769.66015625ns,1.76218974%work gain. Choosing
between already available restored/greedy bits lowers work to545562.8046875ns
(1.79942345%), but this optional mixture was NOT used for authorized native.
The fixed graph is chosen offline by TRAIN work; runtime does not choose32
physical graphs for free. All these values are chip work, not native timings.

Strong controls, prior and limitation
------------------------------------
Same24MiB/384wave useful/page budget funds32complete Down backups, each0.75MiB
and12waves; it does not fund32wholeFFN backups. Before any claim, copy expert
IDs, locations/profiles and selector effort must be fitted comparably, alongside
generic partial RDA, samegraph static repacks and existing g6/down256x6 and
mixed one-copy geometry controls. These heavy controls were not run because
the fixed native gate failed. Thus no relative novelty or gain against those
strong controls is claimed. Generic replicated allocation/flow is already
standard (e.g. Selective Replicated Declustering for Arbitrary Queries,2009,
section2 per-query network flow); no new algorithm/theorem follows here.

The old4MiB single-edge G4 bound did not cover six independent disjoint edges,
so this bounded test was a different finite family. Its modest positive modeled
gain does not establish a new contribution. paper/aif.txt describes block ID,
offset/pagecount dense GEMV and FIFO polling, but maxR/pagecount encodings,
actual output/scaling/reset ABI and controller scatter remain unverified.
kernel/aif.h explicitly provides metadata only, not weights/GEMV outputs.
Clean wave-aligned prefixes remove fringe uncertainty; they do not prove the
remaining native ABI or authorize new hardware functions.
