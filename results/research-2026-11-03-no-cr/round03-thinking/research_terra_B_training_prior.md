# B shared-GU group union: bounded training-source review

This is source/theory only. No model, checkpoint weights, hidden states, target data, book text, candidate code or experiment was read or run. Formal candidate B was already adopted by the parent; this memo does not authorize an implementation or probe. A failed particular initialization/short fit would not establish an impossibility for the representation family.

## What the closest methods actually train

* [PCoMoE §4.2 and §5.1](https://arxiv.org/html/2609.01024v1) uses pretrained MoE experts as full nonlinear source expansions and full Down paths. Diagonal paths are retained; off-diagonal path compatibility is learned and progressively pruned. It fine-tunes with 25,000 Alpaca/SQuAD examples, batch 32, gating LoRA rank 16 and learned compatibility biases; **all expert weights remain frozen**. The paper does not disclose an epoch count in the inspected setup. This is a useful small-data routing-adaptation precedent, not evidence that 25,000 examples or any particular number of hidden states suffices to learn a new shared GU dictionary and new private Downs.
* [ModularMoE §§3.2–3.4, Appendix A and Algorithm 1](https://aclanthology.org/2026.findings-acl.174.pdf) partitions a dense FFN into equal-size activation-co-clustered modules, trains DSelect-k task masks using task loss, thresholds to hard masks, and uses shared masking plus LoRA for multi-task fine-tuning. Appendix A states 32 modules, 16 selected, AdamW, router peak LR 1e-3, adaptation peak LR 3e-4, LoRA rank 8. The inspected paper does not specify the exact optimizer-step count. It evaluates ReLU variants; it does not establish sufficiency of these hyperparameters for post-training a frozen-router SwiGLU expert bank. Its graph/coactivation partition is a meaningful non-random seed control, but is not route-weighted expert-output matching.
* [Mixture-of-Masks §2.2–2.4 and §3/Table 2](https://aclanthology.org/2025.acl-long.768.pdf) begins from all-active dense-model masks, learns sparse masks with hard-concrete/L0 constraints and continues pretraining. Its 300M-model experiments use 20B training tokens; the paper notes that full performance recovery is prolonged. That evidence supports gradual masking as an option, not extrapolation of its downstream score to 30k hidden-state regression. Its original dense-to-MoE setting has a learned router, unlike this fixed-original-router proposal.
* [DERN §3.2–3.3 and Appendix A](https://aclanthology.org/2025.findings-emnlp.820.pdf) uses 128 C4 sequences of length 2048 to collect routing weights/frequency, scores normalized `(gate, up, down)` neuron triplets, initializes clustering preferentially from highly active segments, and uses weighted spherical k-means to reconstruct pruned experts. It is retraining-free original-MoE post-processing, but drops/merges experts, changes the representation and does not fit a fixed-router shared GU dictionary. It motivates a *representative, importance-aware* initialization; it does not validate four whole experts, nor does training-free mean calibration-free.
* [Pruning and Distilling MoE into Dense LMs §§3–4, Appendix J](https://arxiv.org/html/2605.28207v1) evaluates selected original-expert initializations and diversity-aware expert-output selection rather than random FFNs. It reports substantially different outcomes by expert scoring and performs 0.3B-token training per main configuration, with one extension to ~4B tokens; this is a **different dense-student task**, not a proven recipe for B. Its layer-output selection and teacher/student comparisons support a real seeded-vs-random counterfactual, not treating weight similarity as guaranteed functional similarity. Its loss study also cautions that intermediate loss is not automatically superior to final-logit KL.
* [Beyond Retraining-Free MoE Compression §§4–6 and Appendix A](https://arxiv.org/html/2609.06076v1): 3,000 C4 sequences, max 512 tokens, one epoch, effective batch 8, AdamW LR 5e-5, warmup 3%, compare different scopes/objectives. Average full causal-LM fine-tuning recovers 37.3% of the initial compression performance gap across its tested settings; it does not fully close that gap. Those are expert pruning/merging settings, and its best scope updates the entire model, including components B proposes to freeze. This is real evidence that modest post-compression adjustment **can help**, not that it will succeed for a new dictionary or that short per-layer MSE is equivalent. Its 1,024-sequence robustness check is likewise not a universal minimum.
* [GS-MoE §4.1 and Appendix B](https://arxiv.org/html/2610.32009v1) collects one forward pass over 512 sequences of 2048 tokens and fits group-shared linear subspaces plus width reductions without post-training; it explicitly discusses experts with little/no routed calibration. This is an existing train-free alternative and a warning against using overall sample count as a proxy for coverage of each routed expert.

## Initialization and finite fitting proposal

The proposed `M=4I` seed from four actual original experts is **reasonable but unvalidated**. Select source experts using fixed training-only route-weighted importance **and** output/feature diversity or reconstruction coverage, rather than the first four IDs or independently highest-frequency experts. Record selected IDs and seed; DERN's triplet/activation-aware selection or a diversity-aware whole-expert seed is relevant prior, but their exact objectives differ. At this stage one representative seed is enough to start a bounded fit; if it is promising or fitting is ambiguous, a same-budget second initialization (e.g. matched random original experts or alternative representative experts) distinguishes a lucky/unlucky seed from the broader method. No extra teacher validation/test set should be consumed for that choice.

One concrete **illustrative**, not source-certified, first fit is a single candidate configuration on one predefined representative layer: split independently sampled prompts/trajectories into training and model-selection partitions before extracting states; sample across prefill and actual rollout/decode positions; retain the exact original router/cohort/alpha and original shared-expert branch. Initialize GU as source teacher rows, then initialize all expert Down coefficients by regularized regression or a clearly specified data-efficient alternative. Warm up with dense support, then impose an `sI` hard group support and continue optimizing shared GU and Down while keeping router fixed. Treat the dense warm-up model as a *training intermediate* only: the actual hard-support checkpoint must satisfy its deployment format and page-union cost. Track a separately declared soft-to-hard boundary because training only a smooth dense model does not test the deployed sparse representation.

A bounded provisional budget for a system capable of it is **up to 1,000 optimizer updates**, batch size **128 distinct sampled state presentations per update**, with checkpoints after 250/500/1,000 updates and early stopping using only the training-design holdout; split the budget between a short dense warm-up and hard-support refinement and report the split. The exact batch refers to hidden-state presentations, not 128 independent documents or 128 new tokens. For 30,000 distinct train states, 1,000×128 gives about 4.27 state-passes, and correlated states yield fewer independent examples. This is a proposal to expose a learning curve at a bounded cost, **not** an empirical convergence guarantee, a minimum, or a demand to run many competing systems before the first quality test. If compute is insufficient, specify the smaller cap and classify failure as that training configuration's limitation. First perform the frozen hard-student ground-truth quality test only under the parent's approved protocol; do not select hyperparameters or seeds using that test.

Use a mixture-level training objective evaluated on the actual original router cohort and α, plus an explicitly scaled per-expert teacher-output anchor where available; the anchor reduces a degenerate solution that uses cancellation to fit only common cohorts. Record each loss separately, expert selection frequency and effective state coverage. Since teacher outputs for an unselected expert are not normally produced, any deliberate extra teacher queries for under-covered experts require explicit data/compute accounting; do not pretend they come free. Compare training and validation by both prefill and decode, overall energy-weighted mixture error and tail per-expert/cohort error. A model that fits aggregate MSE may still change autoregressive behavior; quality/latency require their separately frozen criteria. Data cannot be selected by peeking at the final held-out benchmark.

## Memory and identifiability: example, not a workload measurement

For H=2048, I=1024, M=4096 and E=64, a shared gate plus up dictionary contains `2*M*H=16,777,216` scalars. Dense temporary expert Down matrices contain `E*H*M=536,870,912` scalars; an s=I deployment support holds `E*H*I=134,217,728` Down scalars before indices/metadata. Standard FP32 parameter + FP32 gradient + two FP32 Adam moments alone cost 16 bytes per scalar, about **8 GiB for the full dense Down** and 0.25 GiB for GU, before teacher, activation, optimizer temporaries, masks and allocator overhead. Alternative precision, offload, sparse/blockwise optimization or sequential updates can change this; no specific peak RAM or runtime is claimed. Offline fitting is not constrained to the 8-GB deployment budget, but its true resources must be recorded.

If 30,000 states route exactly K=6 of 64 experts, total routed assignments equal 180,000 and the mean is 2,812.5 per expert, **without assuming uniformity**. In a hypothetical linear per-expert fit over all M=4096 unconstrained feature coordinates, any expert with fewer than M linearly independent routed states has a rank-deficient unregularized design. The average alone proves neither that each expert is deficient nor real state independence; router imbalance, duplicate/near-duplicate trajectory positions and a validation regime can worsen coverage. Ridge, restricted support, initialization and/or carefully accounted teacher queries help, but do not prove quality. Dense warm-up may also learn coefficients that become poor when 3/4 of columns are later removed; report hard-support loss and convergence separately.

The fundamental unknowns remain: whether a 4I dictionary can represent every important original expert under actual routed states, whether finite fitting identifies it, whether page-aware sparsity improves on an equal-cost mask, and whether natural-language quality and ordinary-read end-to-end latency both pass. None is settled by a source search.
