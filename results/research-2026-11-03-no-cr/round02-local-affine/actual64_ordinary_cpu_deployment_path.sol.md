# Prospective path from C64 quality to an actual64 CPU/load baseline

Same Round2, source/theory only,2026-11-03. Conditional on C64 necessary-quality passage and later explicit source/payload releases. No candidate code, run, model/target/trace/quality bodies or new hyperparameter/search grid. This note does not change the executor's Stage4 sources. Source inspected: existing Stage3 numeric C++/header, Stage4 quality-harness source, pinned llama graph and GGML custom-op declarations.

1. **Reuse the arithmetic, replace the two-template benchmark fixture with the actual64 registry.**

   Stage3's `numeric.cpp` loader explicitly requires two operators, and its natural/full-K loops either visit those two or clone them. Its `numeric.hpp:66–89` forward arithmetic already takes an operator-index vector with at most8 active slots. A future separate C-only helper can therefore reuse the exact tree/P, signed-dot/rescale, bias and slot-order arithmetic while loading the64 actual fitted expert entries and constructing the full real-ID→operator lookup. It need not load/fabricate D/NL arrays that the old combined fixture loader requires. Preserve old files unchanged.

   Bind the C64 registry, all map/scales/bias/support hashes and canonical fallback weights; distinguish actual64 fitted experts from64 physically separate copies of two templates. Legitimate exact coefficient deduplication remains allowed and counted for both CPU and in-flash implementations; do not require actual fitted bytes to differ merely because IDs do. Reuse the already fixed Stage3 TRAIN32 input/provenance/IDs/final-alpha selection at the corresponding early layer, translating collection indices to their verified union identities. This needs no new teacher labels, context capture or quality opening. Report which actual expert/leaf pairs this finite trace visits; loading all64 does not establish that32 inputs cover every expert or workload.

   First compare all raw per-slot outputs and final ordered mixtures against the frozen C64 numeric path, including whole-H canonical fallback where its fixed support policy requires it. Keep old eight-lane FP64 P reduction, sequential FP64 tree rule, A8/scaling and F32 bias/alpha/add order. Then reuse the existing fixed warmups/trials/cache scenarios, persistent8-core execution and raw-time ledger. The result is an actual-map CPU/cohort service measurement, replacing the template approximation; it is not full-model deployment time. One model's complete C32/r128 layer is about.537GB coefficients plus.034GB scales/biases and small common metadata, so the all-resident CPU case is a mandatory strong baseline.

2. **Add one ordinary-read map provider under the same function and explicit cache accounting.**

   Export a new, immutable, page-aligned raw view of those exact map bytes and a signed typed offset/hash manifest; do not time NPZ parsing/decompression as NAND service. Each W8 map is262144B/16 modeled16KiB pages, with scales/bias either explicitly resident or separately fetched. Use real selected expert/leaf addresses, not replicas or independently sampled cache-hit bits. A fixed common interface should supply resident hits or submit ordinary reads for misses; the exact CPU GEMV consumes the same bytes and produces the same result. Allow requests as soon as IDs/leaf are known while common P runs, and allow bounded streaming/asynchronous IO if its buffers and actual scheduling are paid. Provide the same early-prefetch and cache abilities to a later PE path.

   The primary hot-resident case can use the complete single-layer bank. A later bounded miss case must identify the cache budget, initial state, deterministic trace policy, in-flight/read buffers and evictions; a deliberately small-cache stress case is not evidence that the one-layer bank cannot fit DRAM. Include OS page cache and duplicate resident/export buffers in the capacity ledger. Stage3's1GiB cache-line pollution evicts ordinary CPU cache residency; it does **not** establish disk/NAND misses. If a separately approved local-device test uses aligned direct IO, record actual filesystem/device/IO completion behavior; if it uses buffered IO, label page-cache hits and best-effort eviction honestly. No global cache flush, NFS-to-NAND latency substitution, or assumption that bypassing OS cache bypasses the SSD's own cache.

   Separate load/prepack/startup, IO wait, selector/P, exact GEMV, scale/bias/alpha and fallback service, but also measure their attainable joint completion rather than summing standalone wall times. The current EPYC device and CPU measurement is not AiF's modeled i9/ONFI service. Until functional native hardware exists, an AiF ordinary-read/PE timing window remains a separately calibrated model, not a second measured endpoint. No simulator or RTL work is prepaid here.

3. **Replace graph computation before GU, rather than overwrite its completed Down result.**

   Current quality callbacks scatter replacement results at `ffn_moe_down`, after original GGUF Gate/Up, SwiGLU and Down have executed. Subtracting estimated original-FFN time from that harness, or removing Python IPC alone, does not yield deployment latency. The minimal future graph branch is immediately after the unchanged router/top-k/final-weight construction around `llama-graph.cpp:1503`, before GU construction at1514 onward. For the mounted layer only, produce its final H×T routed result from a new CPU custom operator whose explicit dependencies are pre-FFN x, ordered selected IDs and actual final weights. The pinned `ggml_custom_4d` API (`ggml.h:2612`) permits a declared output shape and explicit source tensors; it is a possible implementation hook, not a claim it is already implemented or validated.

   Reuse the exact C-only cohort function inside that operator, returning the already separately weighted/slot-ordered mixture. Do not then multiply alpha again. Return before constructing the replaced original GGUF GU/SwiGLU/Down graph branch. Canonical fallback is evaluated only for actually unsupported selected members, with its real weights/compute charged; it does not justify computing every original source FFN first. Keep source shared/dense, attention/router, later layers, residual and KV behavior unchanged. Trace the actual custom-op weight operand for alpha checks, since the old `ffn_moe_weighted` instrumentation node may now be absent.

   Integrate with GGML's actual worker team or another explicitly reserved executor; nesting the existing standalone8-worker team inside8 active GGML workers would distort the resource comparison. Prove byte equality of the routed mixture and full logits against the frozen C64 overwrite harness under identical GT batching and independent contexts, then verify graph/call counters show zero original GGUF GU/Down execution for the replaced branch. Account canonical fallback separately. Do not count a pruned graph while its discarded tensors are still executed through another forward root or audit callback. Keep numeric/debug shadow recomputation outside timed runs.

   Only after that closure does native B1 timing with real IO/cache providers, preprocessing, scheduler joins and output completion represent a genuine **partial-model deployment**. Existing graph execution need not overlap independent shared work automatically: if submit/compute/join overlap is claimed, demonstrate an actual bounded asynchronous schedule with buffer/event lifetimes, CPU/DRAM contention and the same opportunity for the ordinary provider. A synchronous early prototype remains useful but is not an optimal ordinary-load baseline or proof of PE advantage. Report startup separately and include all retained original tensors, canonical fallback stores, caches, KV and allocator/workspace; skipping computation does not automatically remove source-model loading or its memory cost.

The narrow stopping point is an actual64, numerically identical, no-original-FFN CPU/load execution at the one declared layer. It supplies a strong host implementation and clean native timing entry, not a complete8GB model: current reference GGUF residency can exceed that target, and replacing one early layer does not establish all-depth quality or whole-model10% improvement. Full host-budget closure and adequately covered D/NL/shared-output comparisons remain later requirements. Every step is a future separately gated source/measurement proposal, with no new data or execution authorization here.
