# Reuse audit for a future same-bank ordinary-load / r128-PE model

2026-11-03; same Round2, source/theory only. Inspected source text only. No simulator, compiler, test, candidate, dataset, target, model tensor or new result body was executed/read; current FIT and frozen sources are unchanged. This is a future separately gated executor task, not an implemented functional model or speedup result. The provider/deployment steps remain in `actual64_ordinary_cpu_deployment_path.sol.md`.

## Keep these mechanisms, with their present scope

- **Exact geometry and virtual capacity:** `scripts/research_20261103_ordinary_read_backend.py::split_complete_rows` (79), `lower_rows` (101), `validate_plan` (284) check complete-row coverage, positive dimensions, exact page/wave rounding, input-size limits and block containment. `physical_addresses` (172) checks authoritative descriptors against logical metadata, nonoverlapping wave-aligned LSB addresses and optional per-chip block budgets. Adapt these validators to a **single map phase**, including zero misses, rather than inventing a nonempty dummy Down phase to satisfy the current `(E,2,2)` ABI. The existing address certificate covers coefficient-only virtual LSB storage; it is not FTL, programming, host residency, metadata, overprovisioning or a proof of minimum block count.
- **Explicit ready queues and ownership:** `ReferenceGraph.add/run` (319/360) and `ordinary_read_native.cpp::Graph::add/run` (43/68) provide dependency events, deterministic ready selection, channel/controller/PCIe exclusion, one chip owner from command acquisition through channel-output release, trace invariants and deadlock checks. These are a useful conservative serialization skeleton. `Service.array` / C++ `Config` are an ordered positional ABI: a future contract needs a new version/source, not extra fields silently inserted into the frozen 18-field interface.
- **Independent verification pattern:** `ordinary_read_verify.py::compare_python` (42) compares node-by-node traces plus event costs; its synthetic section (100–147) covers zero-duration nodes, sharing, page fringes and row splits. Reuse the pattern in future newly gated tests; the old tests were not run here and establish neither PE arithmetic nor new resource ownership. `compile.py::assemble_models` (407) also provides a useful cross-layer address/byte ledger pattern, but its own lines440–460 explicitly exclude a real device budget and whole-model time.

The future **ordinary-load builder** reads the identical selected W8 map pages, ECC-corrects, transfers full weight bytes through the declared channel/PCIe/DMA path into finite host buffers, then performs the exact optimized CPU row-dot, rescale/bias and ordered live-alpha mixture. It does not send qV into NAND or emit only I32 results. The **PE builder** retains those same physical reads and ECC capability but adds the explicitly hypothetical short-row command/input RF, PE service, finite staging/FIFO, backpressure, I32 result transfers and host finishing. Its sense/PE overlap is limited by the chosen PB/port ownership contract; no free double buffer or spare latch follows from the old scheduler.

Both arms may submit reads at actual address readiness `max(ID-ready, leaf-ready)` while common P proceeds; tree/P CPU and DRAM costs remain real tasks. Neither sensing path must depend on qV merely because the old matrix function did. Conversely read-before-input for the PE requires its proposed command/hold-PB contract. CPU dot waits for both weights and qV; PE execution waits for its required input/ECC state. Both arms have equal prefetch/read capabilities, cache budget, initial state and deterministic trace policy.

## Minimal new state and proof obligations

Use actual expert/leaf addresses and a joint cache state: the miss set `M_t` (size m) and chip/channel overlap follow from that state, requests, evictions and in-flight fills, not independent hit probabilities or K alone. Include scales/bias, exact-byte deduplication, canonical fallback weights, CPU/OS caches where applicable, read buffers and metadata in inclusive 8e9-byte and 8GiB ledgers. Whole one-layer C64 residency is a mandatory host case, not a capacity impossibility. A PE arm may also exploit the same legal cached maps. Preserve the frozen function and output order in both paths.

The existing graph has **one duration-bearing resource per node**, one whole-command chip owner, and no finite PB, corrected-codeword, output-FIFO, DMA-buffer or host-memory token model. Chip ownership ends before final PCIe drain, so that old graph also implicitly permits downstream buffering without a capacity ledger. A future implementation must add explicit bounded ownership/backpressure (or serialize conservatively), and model CPU worker/DDR contention with source shared work. Do not grant simultaneous peak CPU/DDR services to multiple nodes merely by assigning them different resource IDs. Any multi-resource event extension requires independent validation; a `max` of rates is not an achieved overlap schedule.

`schedule_independent_bounds.py::ledgers/vector_bounds` (52/78) are useful templates for total resource work, causal paths and stated relaxations. Their 513-expert/512-shared indexing, two phases, full-input reloads and I32-only output formulas must change. NAND-only bounds apply only to fixed mandatory uncached waves under the declared layout/cache state. Crucially, its `comparison` (101) compares a **feasible whole-row replay** with a control lower bound; it is not itself a two-LB fallacy. A future claim requires an attainable, fully charged schedule (conditional on explicit service envelopes) versus a valid comparator bound, or comparable measured/validated schedules. Two optimistic lower bounds cannot establish dominance or a speedup.

The smallest subsequent implementation scope is therefore: reuse validators/queue mechanics; create two new versioned single-map DAG builders with actual joint miss state and finite buffers; independently test ownership, bytes, cache transitions, zero/all misses and early-read symmetry before timing sweeps. Ordinary LSB28us, channel/PCIe peaks, PE rate and host services remain labeled model parameters or calibrated envelopes, not silicon maxima or measured AiF performance. None of that implementation/testing is released by this note.
