## Recommended finite sequence

The C-first strategy is reasonable: **freeze the complete prospective version and deferred-control recipes, fit only C64, then test necessary quality; pay for expanded nonlinear controls only if that gate passes.** This saves work on a bounded C64 failure without waiving eventual global/nonlinear/all-host/cache comparisons. C64 passage is not method success, publication readiness or authorization for broader layers.

1. Finish the current Stage3 review under its existing scope. Do not use newly disclosed NL outcomes to tune the C64 recipe. Before a new release, pin the source/numeric/row manifests, all new control transfer rules, budgets, prospective validation identities and stopping analysis below.
2. Build **first64-v1** only at Deep L1 and OLM L0:64 routed experts each. Deep dense L0, source shared and every later layer remain source-GGUF. Keep all old8 artifacts/results immutable. Mount the two passed early-layer C maps per model byte-for-byte; do not mount the later-layer maps in this new version.
3. Query final canonical Y for62 previously unfitted experts per model, once per complete fixed TRAIN union; fit/lower C with the exact transferred recipe. No new GU archive, GU prediction cache, NL Down calibration or expanded D fit is part of this first workload. Canonical Y necessarily computes GU internally, but its temporary intermediates are not silently exported as a second target dataset.
4. Close copy/canonical/CPU/batch/source identity, complete coverage, input-invariance and resource receipts. Freeze all C64 bytes before opening the new validation cohort. Run source, **B64** and C64 independently on that cohort. B64 canonically replaces all64 routed functions at the one early layer; it is not B8, and old B8 NLL cannot be reused.
5. A valid necessary-quality passage allows a separately released control phase, using the same fixed TRAIN inputs/Y and the recipes frozen before step4. Fit/extend all64 NL and the fixed D role-transfer control, then close their own numeric/resource/quality evidence. No automatic GU query, first64 implementation or evaluation is approved by this note.

There is no new on-policy capture in this sequence. The earliest-layer invariant removes intervention-induced input shift **for identical complete token histories and execution settings**. It does not prove statistical coverage or turn old generated continuations into natural GT.

## What this stage can decide

A numeric-valid C64 bounded failure can stop that fixed first-layer version before expensive expanded controls. A valid passage justifies paying for same-data strong controls and considering later-layer coverage. It does not establish full-model quality, a required flash residence or10% whole-model speed: the replaced layer covers only1/16 of OLM routed layers or1/26 of Deep routed layers. Those are coefficient-work fractions, not strict latency bounds or linear NLL scaling laws.

Each complete early-layer bank is about.57GB before small common metadata, so legal all-host identical-bank and original single-layer host/cache controls remain mandatory. Full original OLM may also fit near its known6.8GB floor. Source shared, attention/KV/head, host contention, ordinary-load overlap and unknown PE/FIFO still belong in a complete resource comparison. The remaining substantive decisions before any release are the exact deferred-D default/role map, staged-inference labeling, actual disk root/quota/retention implementation, and a bounded runtime budget based on approved attainable rates. None may be resolved by selecting favorable new validation outcomes.
